# tslua2 任务管理

## 目录结构

```
tasks/
├── README.md              ← 本文件（规范 + 快速索引）
├── open/
│   ├── bug/               ← 待修缺陷
│   └── feature/           ← 待做需求/优化
├── done/
│   ├── bug/               ← 已修缺陷
│   └── feature/           ← 已做需求
└── cancelled/             ← 取消的任务（不删，留记录）
```

## 任务文件规范

文件名：`{编号}-{简短描述}.md`，编号全局递增（001, 002, ...）

文件头模板：

```markdown
# {编号}-{描述}

- **类型**: bug / feature
- **状态**: open / done / cancelled
- **优先级**: P0 / P1 / P2
- **模块**: 所属模块
- **创建**: YYYY-MM-DD
- **完成**: YYYY-MM-DD（完成后填写）
- **阻塞**: 无 / blocked-by: {编号}
- **关联文件**: 涉及的代码文件
- **修复提交**: git commit hash（完成后填写）
```

## 状态流转

```
open → done        完成，mv 到 done/{bug|feature}/
open → cancelled   取消，mv 到 cancelled/
done → open        复发，mv 回 open/{bug|feature}/
```

## Git 分支规范

每个任务对应一个分支，验收通过后合入主分支：

```
主分支: main (或 master)
任务分支: task/{编号}-{简短描述}
例: task/001-数据隔离, task/003-精度全局常量
```

**工作流：**
1. 建单 → `git checkout -b task/xxx`
2. 改代码 → 随时 commit
3. 改完 → 通知陛下切分支验收
4. 验收通过 → 合入主分支
5. 验收不通过 → 继续在分支上改，或回退任务状态

**好处：**
- 主分支始终稳定，不会出现半成品
- 验收不通过直接删分支，主分支零影响
- 每个任务的改动隔离，互不干扰
- git history 清晰，一个分支对应一个任务

## 修改记录规范

- 一个 bug 可能改多次，每次尝试都追加记录，**不覆盖之前的内容**
- 格式：按时间倒序追加，最新的在最上面
- 记录内容：什么问题 → 怎么改的 → 结果（成功/失败/部分解决）

```markdown
## 修改记录

### 2026-05-02 第2次尝试 ✅
**问题**: 第1次修复后配置加载失败，界面回归初始
**改法**: 发现 AttachValueLineEdit 替换 Label 时机不对，改为在 LoadConfig 之后调用
**结果**: 编译通过，配置正常加载，直接编辑功能可用

### 2026-05-01 第1次尝试 ❌
**问题**: 点击数值标签无法直接编辑
**改法**: 在 ConnectSignals 中为所有手动 HSlider 添加 AttachValueLineEdit
**结果**: 编译通过但界面回归初始，配置加载失败，已还原
```
