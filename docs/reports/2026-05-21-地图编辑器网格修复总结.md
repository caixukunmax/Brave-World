# 地图编辑器网格修复总结

日期：2026-05-21
状态：已完成并通过多缩放截图验证

## 1. 问题背景

地图编辑器中的基础网格在相机缩放后会出现以下问题：

- 部分横线或竖线消失。
- 某些缺线具有明显规律性，不像随机故障。
- 视野拉远后，网格一度表现得不像“地面格子”，而更像一层贴在屏幕上的覆盖层。

这类问题会直接影响地图编辑时对格子边界的判断，因此需要结构性修复，而不是继续靠限制最小缩放或抬高线宽来规避。

## 2. 根因分析

本次问题最终确认有三层根因。

### 2.1 旧渲染结构不稳定

早期实现依赖整图 `Line2D` 或世界空间大量矩形几何来绘制网格，但网格线宽又希望保持屏幕像素语义。这样会让以下几个系统耦合在一起：

- 相机缩放
- 世界空间裁剪
- 像素栅格化
- 2D 像素对齐

结果就是在某些缩放与平移位置下，线条会忽粗忽细、局部消失，或需要重新刷新几何才能恢复。

### 2.2 第一版 shader overlay 坐标基准错误

切换到 shader overlay 后，最初一版使用了屏幕空间思路来反推网格坐标，导致网格行为更像一层屏幕覆盖层，而不是地图地面的一部分。

用户提出“地图格子是地面”这一点后，修复方向被进一步收敛为：

- 网格必须使用地图本地坐标对齐。
- 网格必须和地面一起受相机缩放。
- 不能再把网格当成屏幕 HUD 处理。

### 2.3 远视野下的规则性缺线本质是混叠

在改成地图本地坐标之后，仍然观察到“有些线很有规律地渲染不出来”。

最终确认这不是数据丢失，也不是某几条线单独出错，而是典型的子像素采样混叠：

- 网格投影到屏幕后进入子像素范围。
- shader 仍使用“距离小于阈值就画，否则不画”的硬切换。
- GPU 会按照固定采样节奏出现规则性明暗不均或漏线。

因此，这个现象必须通过抗锯齿覆盖计算来解决，不能继续靠线宽补丁处理。

## 3. 修复过程

### 3.1 改为单底板 shader 架构

最终采用 `GridShaderOverlay` 作为 `GridManager` 子节点，负责承载一个覆盖整张地图的 shader 底板。

这样做的核心收益是：

- 不再维护整图 `Line2D` 节点数组。
- 不再依赖大量世界空间 `DrawRect` 作为基础网格。
- 基础网格改为由 shader 直接按地图坐标计算。

### 3.2 网格坐标改为地图本地坐标

shader 中不再使用屏幕空间作为网格坐标来源，而是直接用底板本地 UV 映射到地图世界尺寸：

- 网格位置随地图地面一起缩放。
- 拉远视野时，格子会自然缩小。
- 不再出现“地面不缩小、只有线宽变化”的错误表现。

### 3.3 引入抗锯齿覆盖计算

为了消除规则性漏线，shader 不再使用硬阈值判线，而是采用基于屏幕导数的覆盖率计算：

- 使用 `fwidth` 估算一个像素在网格坐标中的跨度。
- 使用 `smoothstep` 计算网格线在像素上的覆盖率。
- 以覆盖率而不是布尔命中结果来输出透明度。

这一改动直接解决了远视野下“线消失得很规律”的问题。

### 3.4 暴露调试参数

为了方便现场调参，本次把关键参数接入了地图调试面板：

- 网格线宽
- 网格亮度
- 抗锯齿柔化强度

其中抗锯齿柔化强度带有统一的钳制策略，并支持配置持久化。

## 4. 当前实现状态

当前有效版本为 `v4.5`。

### 4.1 当前架构

- `GridManager` 负责地图数据、线宽策略和 shader 参数更新。
- `GridShaderOverlay` 负责承载 shader 材质并绘制整图底板。
- `grid_overlay.gdshader` 负责根据地图本地坐标计算网格线。
- `MapEditor` 右侧诊断文本显示当前版本、缩放、实际线宽、颜色和柔化强度。
- `DebugPanelMapTab` 提供现场调参入口，并支持配置保存/读取。

### 4.2 当前可调参数

地图调试页签已支持以下关键调试项：

- 网格线宽
- 线条亮度
- 抗锯齿柔化强度

其中抗锯齿柔化强度配置键为：

- `map.grid_aa_softness`

其运行时限制策略为：

- 最小值：`0.5`
- 默认值：`1.0`
- 最大值：`3.0`

## 5. 验证结果

本次修复使用自动截图链路在多个缩放档位下反复验证：

- `1.0`
- `0.7`
- `0.5`
- `0.4`
- `0.3`
- `0.2`

验证结论如下：

- 网格在整张地图可见区域内持续存在。
- 拉远视野后，地面格子会随地图一起缩小。
- 规则性漏线现象已消失。
- 网格线宽变化连续，不再出现明显的节奏性缺线。

## 7. 仍未处理的问题

本次修复聚焦于网格渲染链路，未顺手处理以下无关问题：

- 调试面板存在 `toggled` 重复连接告警。
- Godot 退出时仍有若干 RID 泄漏告警。

这些问题与本次网格修复无直接因果关系，因此未纳入当前改动范围。

## 8. 最终结论

这次修复不是单纯调参数，而是完成了一次网格渲染思路的切换：

- 从“不稳定的世界空间几何网格”
- 切换到“地图本地坐标驱动的单底板 shader 网格”

再叠加抗锯齿覆盖计算和调试面板参数化，最终达成了以下目标：

- 网格稳定
- 远视野不规则漏线消失
- 地面格子行为正确
- 调参能力可用
- 自动化验证可回归
