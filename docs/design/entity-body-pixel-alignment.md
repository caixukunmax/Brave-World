# 实体方块像素对齐

## 1. 背景

当前玩家、野怪、NPC 的方块本体虽然共享同一套外观参数，但在某些截图里仍会出现：

- 同样参数下，某一张看起来更宽一点
- 尤其底部轮廓更容易出现“胖瘦不一致”的感觉

这说明问题已经不在标签布局，而在实体本体的像素轮廓稳定性。

## 2. 根因

当前方块绘制仍然存在两层不稳定因素：

1. `VisualOuterSize / BorderWidth` 允许带小数参与最终轮廓计算
2. 边框通过描边式圆角路径绘制，容易受半像素落点影响

结果就是：

- 同样配置
- 在不同截图或不同位置
- 边框可能会因为描边落点不同，看起来宽 1px 左右

## 3. 目标

1. 同样参数必须得到同样像素轮廓
2. 边框始终向内吃，不允许再把轮廓向外撑胖
3. 点击命中范围与可见外轮廓一致

## 4. 方案

### 4.1 整数像素语义

统一把实体本体核心尺寸收口为整数像素：

- `VisualOuterSize`
- `BorderWidth`
- `VisualSize`

其中：

- `VisualOuterSize`：总外轮廓尺寸
- `BorderWidth`：整数像素边框宽度
- `VisualSize`：内部填充尺寸，按 `VisualOuterSize - BorderWidth * 2`

### 4.2 边框改为内缩填充

不再使用“沿轮廓线描边”的方式作为最终边框。

改为：

1. 先画外层边框色圆角矩形
2. 再画向内收缩后的背景色圆角矩形

这样边框完全向内吃，外轮廓不会因为描边宽度而外扩。

### 4.3 中心填充不受边框底色污染

在“先画边框色外层、再画中心填充”的双层方案下，如果中心填充继续使用半透明颜色直接叠加，
就会出现一个副作用：

- 背景色会和下方边框色混色
- 例如：纯黑 + 低不透明度 + 红边框
- 最终中心看起来会变成酒红色，而不是用户想要的黑色

因此中心填充需要先解析成最终可见色，再以不透明方式填入。

当前项目在黑底地图上的等效规则是：

- `finalFillRgb = bgColor.rgb * bgOpacity`
- `finalFillAlpha = 1`

这样：

1. 纯黑永远保持纯黑
2. 红色低不透明度会表现成深红
3. 中心区域不会再被边框底色污染

### 4.3 命中范围同步

实体点击判定与 `HitTest` 应基于 `VisualOuterSize`，而不是内部填充尺寸。

否则会出现：

- 看得见的边框能点到
- 但代码命中范围却更小

## 5. 验收标准

1. 同样参数截图对比时，方块本体宽度不再一会儿胖一会儿瘦
2. 底部轮廓在不同截图里保持一致
3. `scale = 1.0` 时，含边框的总外轮廓仍然贴格子内边，不越界
