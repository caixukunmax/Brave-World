# 怪物 AI 设计

> 状态：已实现
> 范围：`servercsharp/src/GameServer.GameLogic/Monster/`

---

## 1. AI 状态分层

## 1. 背景

当前怪物运行时已经有 `InCombat` 状态，但 `MonsterManager.Tick()` 仍然统一调用 `patrol / patrol_chase / guard` 这类大地图 AI。

这会导致：

1. 非战斗 AI 仍在决定怪物往哪里走。
2. 战斗系统又在部分分支里拦截移动和碰撞。
3. `InCombat` 没有成为真正的高层行为切换入口。

最终表现就是怪物进入战斗后，容易出现“突然不动”“追一下又停”“行为语义不稳定”。

这不是单点 bug，而是高层状态机缺位导致的历史设计债暴露。

## 2. 设计目标

本轮目标不是重写整套怪物技能 AI，而是先把怪物行为明确拆成两层：

1. 非战斗 AI：负责巡逻、警戒、发现目标、回出生点。
2. 战斗 AI：负责进入战斗后的追击、贴身、等待技能 CD 就绪后释放。

要求：

1. `InCombat` 必须成为高层调度开关，而不是零散条件分支。
2. 进入战斗后，不再继续跑 `patrol`/`patrol_chase` 的完整逻辑。
3. 第一阶段保持最小行为正确，不引入远程怪、施法怪等复杂分支。
4. 脱战后必须能回到非战斗 AI，而不是残留在半战斗状态。

## 3. 分层方案

### 3.1 高层模式

怪物运行时分为两种高层模式：

1. `Overworld`
   - 条件：`InCombat == false`
   - 行为来源：`patrol / patrol_chase / guard`
2. `Combat`
   - 条件：`InCombat == true`
   - 行为来源：统一战斗行为入口

`MonsterManager.Tick()` 先决定模式，再决定具体行为。

### 3.2 第一阶段保留的非战斗 AI

当前表里的 AI 类型先不变：

1. `patrol`
2. `patrol_chase`
3. `guard`

它们全部归类为“非战斗 AI”。

其中 `guard` 继续复用 `patrol_chase`，只是配置上更偏向原地警戒。

### 3.3 第一阶段新增的战斗 AI

第一阶段新增统一的 `CombatChaseBehavior`，行为规则如下：

1. 怪物已在战斗中时，优先追踪当前 `TargetId`。
2. 若 `TargetId` 无效，则尝试从当前地图玩家中重新选择最近目标。
3. 若目标与怪物相邻，则不主动位移，等待战斗系统处理攻击。
4. 若目标不相邻，则按 `chase_interval_ms` 进行一步追击。
5. 若下一步目标格已有敌对实体，则直接触发碰撞检查，不再走“先移动 30% 再弹回”的流程。

这样可以保证：

1. 相邻时不会来回抖动。
2. 拉开距离时会重新追上去，不会因为切到战斗状态就彻底停住。
3. 战斗中的移动语义与非战斗巡逻分开。

## 4. 运行时状态约定

### 4.1 `InCombat`

`InCombat` 继续作为权威高层模式开关。

### 4.2 `TargetId`

本轮补充约定：

1. 怪物受伤进入战斗时，默认将攻击者写入 `TargetId`。
2. 怪物脱战时，清空 `TargetId`。

这能避免战斗态里没有追踪对象，只能依赖模糊的“最近玩家”回退。

### 4.3 `State`

`State` 继续保留字符串形式，但语义区分为两层：

1. 非战斗态：`idle / patrol / chase / return`
2. 战斗态：`combat / combat_hold / combat_chase`

本轮不强制把 `State` 升级成 enum，但要求日志和调试时能分辨当前处于哪一层。

## 5. 脱战行为

怪物脱战时：

1. `InCombat = false`
2. `TargetId = null`
3. `State = "return"`

这样脱战后下一个 tick 会重新走非战斗 AI，并优先回到出生点附近，而不是残留在战斗追击语义里。

## 6. 第二阶段：战斗行为类型

第一阶段只有统一的 `CombatChaseBehavior`，足够把“进入战斗后站桩”修正为“进入战斗后能追击”。

第二阶段开始，战斗 AI 继续细分为三类：

1. `Melee`
2. `Ranged`
3. `Caster`

### 6.1 来源规则

战斗行为类型的来源按以下优先级决定：

1. **AI 表显式覆盖**
   - 复用 `common_tbai.json` 的 `param_1`
   - 约定：
     - `0 = Auto`
     - `1 = Melee`
     - `2 = Ranged`
     - `3 = Caster`
2. **自动推断**
   - 当 `param_1 = 0` 时，根据怪物技能池自动推断

### 6.2 自动推断规则

自动推断只做“最小正确”，规则如下：

1. 若怪物没有任何技能配置，默认 `Melee`
2. 若怪物技能最大 `cast_range <= 1`，判定为 `Melee`
3. 若怪物存在 `cast_range > 1` 且对应技能 `cast_time > 0`，判定为 `Caster`
4. 若怪物存在 `cast_range > 1` 但没有读条技能，判定为 `Ranged`

### 6.3 行为规则

#### `Melee`

1. 目标距离 `<= 1` 时停在原地，等待战斗系统出手
2. 目标距离 `> 1` 时追击到贴身

#### `Ranged`

1. 使用怪物技能池中的最大 `cast_range` 作为接战距离
2. 目标距离 `<= cast_range` 时停在原地
3. 目标距离 `> cast_range` 时追击到可攻击距离

#### `Caster`

第一阶段先与 `Ranged` 保持相同位移策略：

1. 追到可施法距离后停下
2. 不在本轮引入风筝、后撤、预判走位

区别只体现在行为类型和状态命名上，给后续扩展留挂点。

### 6.4 运行时约定

`AiConfig` 增加战斗行为类型字段，运行时保留最终决议结果，供：

1. `MonsterManager.Tick()` 分发不同战斗行为
2. 调试日志输出
3. 后续 DebugPanel / GM 面板观察

### 6.5 当前样板配置

为了让第二阶段能在现有地图里直接观察差异，本轮约定先落三类样板 AI：

1. `id=2`
   - `ai_type = patrol_chase`
   - `param_1 = 1 (Melee)`
   - 用于近战样板
2. `id=4`
   - `ai_type = patrol_chase`
   - `param_1 = 2 (Ranged)`
   - 用于远程样板
3. `id=5`
   - `ai_type = guard`
   - `param_1 = 3 (Caster)`
   - 用于施法样板

`xinshoucun` 当前样板分配：

1. `monster_id = 1` 继续使用近战样板
2. `monster_id = 2` 改为远程样板
3. `monster_id = 3` 改为施法样板

这样进入同一张地图后，就能直接观察：

1. 近战怪是否会贴身
2. 远程怪是否会在技能距离内停住
3. 施法怪是否也会保持施法距离，而不是继续贴脸

## 7. 本轮不做

以下内容明确不在本轮范围内：

1. 施法怪的风筝/后撤逻辑
2. 战斗技能选择器重构
3. 仇恨列表系统
4. 多目标战斗优先级系统
5. 将 `guard` 改成独立实现

## 8. 后续扩展方向

本轮改造完成后，后面可以在不污染非战斗 AI 的前提下扩展：

1. `MeleeCombatBehavior`
2. `RangedCombatBehavior`
3. `CasterCombatBehavior`
4. 基于怪物模板或 AI 表决定“战斗行为类型”

到那时顶层结构仍然保持：

1. `OverworldBehavior`
2. `CombatBehavior`
3. `MonsterManager.Tick()` 只做调度，不承载所有细节

## 8.1 领地提示

为了让“战斗信息面板”能更直观地表达野怪与玩家的接触关系，本轮补一层轻量叙事提示，直接复用 `CombatLogNotify`：

1. **闯入领地**
   - 触发条件：玩家坐标首次跨入该怪物的巡逻区域边界
   - 显示文案：`{玩家名}闯入了{怪物名}的领地`
2. **脱出范围**
   - 触发条件：玩家从该怪物的巡逻区域内跨出边界
   - 显示文案：`{玩家名}逃走了,{怪物名}找不到目标`

### 约束

1. 这类提示属于 AI 叙事，不属于技能/伤害/死亡日志，所以不挂到 `CombatManager` 的技能结算链上。
2. 直接复用 `CombatLogNotify`，避免新增客户端面板协议。
3. 领地边界必须使用和怪物巡逻一致的区域定义，不能拿 `aggro_range` / `TargetId` 代替。
4. 同一只怪物对同一个玩家只在“跨入边界”时发一次闯入提示，不能每个 tick 刷屏。
5. 玩家离开区域后要清空这次叙事上下文，允许下次重新进入领地时再次提示。

## 9. 验收标准

1. 怪物进入战斗后，目标拉开距离时会继续追击，不会直接停住。
2. 怪物与目标相邻时不会反复尝试无效位移。
3. 怪物脱战后能恢复到非战斗 AI，并回归出生点/巡逻状态。
4. `MonsterManager.Tick()` 中不再出现“非战斗 AI + 战斗特判硬拼接”的混合结构。
5. 同一套战斗调度下，近战怪会贴身，远程/施法怪会在技能距离内停住。

## 2. 近战阶段收口

## 1. 背景

当前怪物 AI 已经拆分出 `Overworld / Combat` 两层，但现网样板怪同时混入了近战、远程、施法三类战斗行为和中距离技能。

这在“战斗态追击”还没有完全调顺之前，会引入一个放大器问题：

1. 怪物一旦拿到 `cast_range > 1` 的技能，战斗 AI 很容易提早判定“已经到攻击距离”
2. 玩家看到的是怪物进入战斗后原地停住，误以为 AI 失效
3. 问题根因不在单个 `if`，而在于当前阶段的玩法目标和配置复杂度不匹配

因此，本轮不继续硬调远程/施法手感，而是先把当前可玩阶段统一收口成“怪物只使用近距离攻击技能”。

## 2. 本轮目标

本轮只做三个明确目标：

1. 怪物进入战斗后，应主动贴近玩家，直到相邻后再等待战斗系统出手
2. 当前样板怪只配置近距离攻击技能，不再混入中距离技能
3. 当前怪物技能统一不消耗蓝条，数据和运行时语义保持一致

## 3. 阶段约束

### 3.1 战斗行为约束

当前阶段，地图里的样板怪统一视为 `Melee`：

1. `combat_range = 1`
2. 目标距离 `> 1` 时必须持续追击
3. 只有在相邻时才允许进入 `hold`

远程怪、施法怪的行为骨架仍然保留在代码里，但不作为当前地图样板的正式配置使用。

### 3.2 技能池约束

当前阶段，怪物技能池只保留 `cast_range <= 1` 的技能。

新手村样板怪约定：

1. `monster_id = 1`
   - 保留：`2, 26`
2. `monster_id = 2`
   - 保留：`2, 3`
   - 移除：`27`
3. `monster_id = 3`
   - 保留：`12, 26`
   - 移除：`13, 27`

### 3.3 蓝耗约束

当前阶段，怪物技能统一不消耗蓝条。

要求分两层成立：

1. 运行时：怪物施法不参与玩家 MP 检查与扣除
2. 配置层：怪物实际使用到的技能 `mp_cost = 0`

这样可以避免“逻辑上不扣蓝，但日志/配置仍像要扣蓝”的语义分裂。

## 4. 实施方式

### 4.1 AI 配置

新手村当前使用到的样板 AI 全部收口为近战：

1. `ai_id = 2` 保持 `Melee`
2. `ai_id = 4` 从 `Ranged` 改回 `Melee`
3. `ai_id = 5` 从 `Caster` 改回 `Melee`

### 4.2 技能配置

怪物表里移除当前阶段不用的中距离技能；同时把仍在使用的怪物技能蓝耗设为 `0`。

## 5. 本轮不做

以下内容明确不在本轮范围内：

1. 远程怪保持距离
2. 施法怪读条后撤
3. 怪物技能优先级重构
4. 远程/施法样板重新投放到地图

## 6. 验收标准

1. 怪物进入战斗后，目标不相邻时会主动追击
2. 新手村当前三种样板怪都按近战方式贴身
3. 当前样板怪技能池不含 `cast_range > 1` 的技能
4. 当前样板怪技能 `mp_cost = 0`
