# 技能管线设计稿（Skill Pipeline Design）

> 版本：V0.3  
> 状态：玩法已确认，边界条件已澄清，可进入技术设计

---

## 1. 设计目标

构建一套**标准化、可扩展、与 ATB 自动战斗完全兼容**的技能执行管线（Skill Pipeline）。

- **标准化**：所有技能（包括普攻）走同一套流程。
- **可扩展**：新技能只需配置表 + Action 组合，无需修改核心代码。
- **高兼容**：与"距离尊重原则"、"单角色单 ATB"、"大地图即时战斗"无冲突。
- **风筝友好**：读条期间默认允许移动，不因走位而惩罚玩家施法意愿。

---

## 2. 核心设计哲学

### 2.1 技能 = Action 序列

- 一个技能的最终效果不是写死在代码里的，而是由**一个或多个 Action 组合**而成。
- **Action** 是技能效果的最小原子单元，例如：
  - `DealDamage`：造成伤害
  - `Heal`：恢复生命
  - `ApplyBuff`：施加增益/减益
  - `ApplyDebuff`：施加负面状态
  - `Teleport`：瞬移到指定位置
  - `Knockback`：击退目标
  - `SpawnProjectile`：生成投射物（后续独立飞行并触发命中 Action）
  - `SpawnArea`：生成范围伤害区域（AOE 持续伤害）

### 2.2 管线化执行

技能的释放不是"一个函数走到底"，而是经过多个**严格分离的阶段**。每个阶段都有明确的输入、输出和失败处理。

## 3. 技能管线流程（Skill Pipeline Flow）

```
┌─────────────────────────────────────────────────────────────────────┐
│  阶段 0: Cast Request (施法请求)                                      │
│  ─────────────────────────                                          │
│  触发来源: ATB 系统通知 AI "该角色可以行动了"                           │
│  AI 根据当前战斗关系，选定一个候选技能 SkillId                         │
└──────────────────┬──────────────────────────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────────────────────────────┐
│  阶段 1: Pre-Check (前置条件检查)                                     │
│  ────────────────────────                                           │
│  检查不依赖具体目标的静态条件:                                         │
│  - 技能是否在冷却中 (Skill CD)                                        │
│  - 自身状态是否允许施法 (是否被沉默/眩晕/禁锢)                         │
│  - 资源是否足够 (MP / 能量 / 特殊资源)                                 │
│  - 是否需要特定武器/装备                                               │
└──────────────────┬──────────────────────────────────────────────────┘
                   │ 失败 → 返回 Failure，进入"跳过 + ATB 补偿"逻辑
                   ▼ 成功
┌─────────────────────────────────────────────────────────────────────┐
│  阶段 2: Target Selection (目标选择)                                  │
│  ──────────────────────────                                         │
│  根据技能的 TargetType 和当前战斗关系，选出一个或多个目标。              │
│  目标选择 ALREADY 受 castRange 约束，只会在射程内筛选。                │
│  - Self: 自身                                                         │
│  - SingleEnemy: 当前战斗关系中的单个敌人 (按仇恨/距离/血量等规则排序)    │
│  - SingleAlly: 单个友方                                               │
│  - AllEnemiesInRange: 范围内所有敌人                                  │
│  - AllAlliesInRange: 范围内所有友方                                   │
│  - GroundPos: 地面指定位置 (通常由 AI 根据敌人位置计算最佳落点)          │
└──────────────────┬──────────────────────────────────────────────────┘
                   │ 失败 (无有效目标) → 返回 Failure
                   ▼ 成功
┌─────────────────────────────────────────────────────────────────────┐
│  阶段 3: Cast Start (开始施法)                                        │
│  ───────────────────────                                            │
│  正式进入施法状态:                                                    │
│  - 扣除 MP / 资源                                                     │
│  - 进入"施法中"状态标志                                                │
│  - 如果有读条时间 (CastTime > 0):                                     │
│    - 播放施法动作/特效                                                │
│    - 移动是否打断? → 根据技能配置决定 (interruptOnMove)               │
│    - 默认: 尽可能不打断，允许玩家风筝走位                               │
│  - 如果 CastTime == 0 (瞬发):                                         │
│    - 直接进入阶段 4                                                   │
└──────────────────┬──────────────────────────────────────────────────┘
                   │ 被强制中断 → 返回 Interrupt
                   ▼ 正常完成读条
┌─────────────────────────────────────────────────────────────────────┐
│  阶段 4: Final Validation (终局验证)                                  │
│  ─────────────────────────                                          │
│  在技能真正释放前，基于当前时刻再做一次最终条件校验:                      │
│  - 与目标的距离是否仍在施法距离 (CastRange) 内                         │
│  - 目标是否仍存活                                                      │
│  - 目标是否处于不可选中/无敌状态                                        │
│  - 自身与目标之间是否有地形阻挡                                        │
│  ⚠️ 对于 AOE/范围类技能，如果原主目标死亡/跑出范围，尝试重新在施法距离    │
│     内寻找另一个合法目标；若找不到，则算"打空"。                         │
│  ⚠️ 此处失败 = "打空"，MP 不返还，技能进入完整 CD。                      │
│     ATB 清零，并触发"下次积累加速补偿"。                                 │
└──────────────────┬──────────────────────────────────────────────────┘
                   │ 失败 → 返回 Failure (Miss)
                   ▼ 成功
┌─────────────────────────────────────────────────────────────────────┐
│  阶段 5: Main Execution (主逻辑执行)                                  │
│  ─────────────────────────                                          │
│  按顺序执行该技能配置的所有 Action:                                     │
│  - Action 1: DealDamage                                               │
│  - Action 2: ApplyBuff                                                │
│  - Action 3: SpawnProjectile                                          │
│  每个 Action 内部再分: 前处理 → 执行 → 后处理                           │
└──────────────────┬──────────────────────────────────────────────────┘
                   │
                   ▼
┌─────────────────────────────────────────────────────────────────────┐
│  阶段 6: Cast End (施法结束)                                          │
│  ───────────────────────                                            │
│  - 记录技能完整冷却时间                                                │
│  - 清除"施法中"状态标志                                                │
│  - 如果有后摇时间 (PostCastTime > 0):                                 │
│    - 进入"后摇"状态，期间允许移动，但不能再次释放技能                   │
│  - ATB 清零 (由 ATB 系统接管下一次积累)                                │
│  - 触发施法后事件 (OnCastEnd)                                          │
└─────────────────────────────────────────────────────────────────────┘
```

## 4. 关键机制详解

### 4.1 读条期间移动（移动不打断为默认）

- **绝大多数技能**的 `interruptOnMove = false`，允许玩家在读条期间继续风筝走位。
- 只有极少数需要"站桩吟唱"的大技能（例如全屏 AOE、超长读条大招）才配置 `interruptOnMove = true`。
- 读条期间如果玩家撞到新的怪物/玩家：
  - **不影响当前读条**，正常进入阶段 4（Final Validation）。
  - 新增的战斗关系由碰撞系统独立处理。

### 4.2 "打空"机制（Final Validation 失败）

- **场景**：玩家边跑边读火球术，读条结束时目标已经跑出了射程/死亡/无敌。
- **AOE/范围技能的特殊处理**：
  - 如果原主目标失效，但 `castRange` 内仍有其他合法敌人，**自动切换为最近目标**，技能正常释放。
  - 如果范围内已无任何合法目标，才算"打空"。
- **打空结果**：
  - MP **不返还**（资源已消耗）。
  - 技能进入**完整 CD**。
  - ATB **清零**。
  - 触发**下次 ATB 积累加速补偿**（有上限，避免无限叠加）。

> **设计意图**：玩家选择风筝走位，就要承担"可能打空"的风险；但补偿加速让这种风险不会过于惩罚，保持战斗流畅。

### 4.3 后摇机制（PostCastTime）

- 所有技能可配置后摇时间，普攻的后摇通常极短（0.1~0.2 秒）。
- **后摇期间允许移动，移速不受影响**。
- 但后摇期间**不能再次释放技能**。
- ATB 的积累在后摇期间**正常进行**，只是如果 ATB 提前满了，需要等后摇结束才能发起下一次 `CastRequest`。

### 4.4 没有公共冷却（GCD）

- 各技能拥有独立的 CD 和后摇。
- **不存在全技能共享的公共冷却**。
- 后摇机制已经足够防止高迅捷角色的技能连发抽搐。

## 5. Action 系统设计

### 5.1 Action 接口定义

```lua
-- 伪代码
function Action:execute(caster, targets, context)
    -- caster: 施法者
    -- targets: 目标列表
    -- context: 本次技能释放的上下文 (技能 ID、等级、命中坐标等)
    -- 返回: { success = true/false, results = {} }
end
```

### 5.2 内置 Action 清单（第一版）

| Action | 作用 | 参数示例 |
|--------|------|----------|
| `DealDamage` | 对目标造成伤害 | `damageType=physical`, `formulaId=1`, `coefficient=1.2` |
| `Heal` | 恢复目标生命 | `formulaId=2`, `isPercent=false` |
| `ApplyBuff` | 施加增益状态 | `buffId=1001`, `duration=10s`, `stacks=1` |
| `ApplyDebuff` | 施加减益状态 | `debuffId=2001`, `duration=5s` |
| `Teleport` | 将施法者瞬移到目标位置 | `targetPos=groundPos` |
| `Knockback` | 击退目标 | `distance=3` |
| `SpawnProjectile` | 生成投射物 | `projectileId=1`, `speed=10`, `onHitActions=[...]` |
| `SpawnArea` | 生成 AOE 区域 | `radius=3`, `duration=5s`, `tickInterval=1s`, `tickActions=[...]` |
| `RestoreMP` | 恢复 MP | `value=50` |
| `ConsumeHP` | 消耗自身 HP 作为代价 | `value=20` |

## 6. 与 ATB 战斗系统的兼容性审查

### 6.1 ✅ 无冲突点

| 机制 | 兼容性说明 |
|------|-----------|
| **碰撞触发战斗** | 碰撞 = 立即执行一次简化管线（跳过读条，直接 DealDamage）。 |
| **单角色单 ATB** | ATB 满时发起 `CastRequest`，整个管线只占用一条 ATB 周期。 |
| **普攻即技能** | 普攻是 `skillId=1` 的配置，完整走管线。 |
| **大地图即时战斗** | 所有 Action 直接作用于大地图坐标，不切换场景。 |
| **脱战机制** | 脱战后该角色的所有战斗关系清空，未完成的读条/后摇强制中断。 |
| **无公共 GCD** | 后摇 + 独立 CD 已足够控制节奏，无需额外的 GCD 层。 |

### 6.2 ⚠️ 潜在风险与处理方案

#### 风险 1: 移动读条 + 大地图碰撞

**问题**：玩家在读条期间移动，撞到了第三个怪物，会不会导致读条被打断？

**处理**：
- **不会**。移动本身不打断读条（默认 `interruptOnMove=false`）。
- 撞到新怪物只会由**碰撞系统**新增一条战斗关系，与当前读条是平行事件。
- 当前技能在阶段 4（Final Validation）时，只校验**原目标**是否还合法（AOE 会尝试重选），不会因为多了新战斗关系而失败。

#### 风险 2: 读条期间目标死亡

**问题**：玩家读条时，目标被队友打死了。阶段 4 校验失败 → 打空。

**处理**：
- 对于单体技能：这是预期行为，打空后给予 ATB 补偿加速。
- 对于 AOE 技能：阶段 4 会尝试在范围内切换新目标，找不到才算打空。

#### 风险 3: 后摇期间再次碰撞

**问题**：玩家刚放完一个技能进入后摇，又撞到一个新怪物。此时 ATB 可能还没满，但碰撞是否能立即先手攻击？

**处理**：
- **碰撞的先手攻击是一个简化管线**，不消耗 ATB、不检查后摇。
- 后摇只限制"ATB 满后的主动技能释放"，不限制碰撞触发的普攻。
- 本能反击不应该被自己的后摇卡住。

#### 风险 4: 弹道技能的"二次验证"与阶段 4 的边界

**问题**：火球术读条 0.5 秒，但弹道飞行又要 1 秒。目标在读条结束时合法，但飞行途中跑远了/死了，怎么办？

**处理**：
- **阶段 4 的验证**只保证"允许释放这个技能/允许射出这个火球"。
- **弹道命中时的验证**（在 `SpawnProjectile` 的 `onHitActions` 里）再做一次。
- 如果命中时目标已死亡/脱战，则 `DealDamage` 不生效，火球表现为"划过目标打空"。
- 这不会触发 ATB 补偿（因为 ATB 周期在读条结束时就已经正常结算了）。
- 这是投射类技能的天然特性，玩家可以接受。

#### 风险 5: 补偿加速的叠加

**问题**：如果玩家连续风筝导致连续打空，补偿加速是否可以无限叠加？

**处理**：
- **设置补偿上限**。例如最多叠加 2 层，或最多提供 50% 的加速。
- 否则高迅捷角色可能因为反复打空而进入"几乎无限快"的 ATB 循环，破坏平衡。

## 7. 状态与并发关系总结

一个角色在同一时刻可能处于以下状态之一或组合：

| 状态 | 可移动 | 可释放技能 | 可被碰撞触发普攻 | 备注 |
|------|--------|------------|------------------|------|
| **空闲 (Idle)** | ✅ | ✅ (ATB 满时) | ✅ | 未进入战斗状态 |
| **战斗中 + 读条 (Casting)** | ✅ (默认) | ❌ | ✅ | `interruptOnMove` 为 true 时移动打断 |
| **战斗中 + 后摇 (PostCast)** | ✅ | ❌ | ✅ | ATB 正常积累 |
| **战斗中 + ATB 已满等待后摇** | ✅ | ❌ (等后摇) | ✅ | 后摇结束立即释放 |
| **战斗中 + 非读条非后摇** | ✅ | ✅ (ATB 满时) | ✅ | 正常可释放 |
