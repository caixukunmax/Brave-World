## 1. 定位与范围

导演模式用于编排**单人剧情演出**：在客户端本地按脚本顺序执行一系列演出指令（cue），包括对白、角色气泡、NPC 走位、镜头运动、黑场/黑边等，演出结束后恢复游戏状态。

**形态 = 运行时系统 + 编辑器插件 + JSON 资源**：

- **运行时**：游戏客户端内的编排器（`Scripts/Cutscene/`），负责播放演出；
- **编辑器**：Godot 编辑器插件（`addons/cutscene_editor/`），负责可视化编排演出脚本（对照项目已有 `addons/*_editor` 插件先例）；
- **数据**：每场演出一个 JSON 文件，放在 `clinetcsharp/data/cutscenes/` 下，插件写、运行时读，是唯一数据源。**不走 Luban/Excel 链路**（演出数据本质是"地图资源"而非"数值配置"，且需要编辑器直接读写）。

### 已确认的决策

| 决策点 | 结论 |
|--------|------|
| 驱动方式 | **客户端本地驱动**。服务器不参与演出过程；单人剧情各看各的，不要求多人同步 |
| 角色表现力 | **无角色动作动画**（项目无 AnimationPlayer，实体为色块占位）。用**头顶气泡**（文字/表情符号）+ **状态栏**（血条、施法条等已有组件）表达角色情绪与状态；镜头、黑边、黑场、走位等其他手段正常使用 |
| 脚本格式 | **JSON 资源文件**（详见 §4），线性为主，支持并行组；选项分支留到第二期 |
| 编辑方式 | **Godot 编辑器插件可视化编排**（详见 §5）；游戏内 GM 命令负责真实效果回放 |
| 状态影响 | **纯播放原则**（2026-07-22 确认）：演出不修改任何真实游戏状态。move cue 对真实实体（NPC/怪物/玩家）只做客户端视觉位移，不同步 GridPos、不与服务器交互；退出演出时视觉位置自动还原。剧情需要永久改变世界状态（NPC 消失、玩家传送等）属于第二期，届时走服务器协议 |

### 非目标（第一期不做）

- 多人同步演出、服务器权威演出
- 角色骨骼/帧动画、立绘
- BGM/音效管理器（项目当前无音频资产，脚本格式预留字段）
- 选项分支对话树
- 插件内的**真实**运行时预览（游戏需连服务器进图，编辑器进程做不到；真实效果仍以游戏内 GM 热重载回放为准。插件内提供 §5.4 的模拟预览）
- 剧情进度服务器持久化（第一期用本地文件）

## 3. 客户端运行时架构

```
CutsceneDirector (Node, ProcessMode=Always, 挂在 Main 下)
├── CutsceneContext          // 演出上下文：actor 注册表、镜头快照、跳过请求
├── handlers/ 各 ICueHandler // 每种 cue 一个执行器，async 返回完成
├── LetterboxOverlay (新建)  // 上下黑边，CanvasLayer
├── BubbleLayer (新建)       // 实体头顶气泡，跟随实体
└── StoryActor (新建)        // 本地假实体，复用 EntityBase 绘制管线
```

### 3.1 CutsceneDirector

职责：加载演出脚本 → 进入演出态 → 顺序执行 cue →（跳过或完成后）恢复现场。

演出态进入/退出（exactly once，成对执行）：

1. 进入：`UIInputPolicy.PauseGame()` 暂停世界 → `GameUiVisibilityManager.HideGameUi()` 隐藏 HUD → 保存 `CameraController` 状态快照（Target/position/zoom，参照其 `SetEditorMode` 的快照做法）→ 镜头进入演出模式（屏蔽拖拽/滚轮输入）。
2. 退出：镜头恢复快照并退出演出模式 → `ShowGameUi()` → `ResumeGame()` → 销毁全部 StoryActor 和残留气泡/黑边。

**关键实现约束**：`PauseGame()` 会冻结整棵树，因此 Director 自身及所有演出节点必须 `ProcessMode=Always`；走位等 Tween 必须由 Director（Always 节点）创建，不能由被暂停的实体节点创建，否则 Tween 一并冻结。StoryPanel 已是 `ProcessModeEnum.Always`，可直接在暂停中工作。

### 3.2 演员寻址（Actor 寻址）

cue 中用演出内声明的**演员 id（整数）**引用"演员"（见 §4.1 演员表）：

- 演出开头在 `actors` 数组声明演员 `{ id, type, monsterConfigId }`，`type`：`1=玩家`、`2=怪物`。
- 后续 cue（`move`/`face`/`bubble`/`actor_enter`/`actor_leave`/`camera_focus`/`dialogue`）的 `actor` 字段填该整数 id。
- 演员默认不在场，需先 `actor_enter`（带落点）登场，再被引用；`actor_leave` 退场。
- 演出演员全部是本地假人（玩家用预设外观、怪物按 `monster_config.json`），与服务器同步的真实实体无关——剧情对真实游戏零影响。

寻址失败的处理：屏幕弹错误提示并中断演出、走恢复流程（见 §6 制作侧体验要求 #2）。

### 3.3 中断与跳过

- 玩家按 ESC 请求跳过：设置 `CutsceneContext.SkipRequested`，当前 cue 尽快结束（Tween 直接 finish），Director 不再取后续 cue，直接走退出恢复流程。
- 演出期间网络断线/服务器强推传送等异常：以退出恢复流程兜底，保证 HUD、镜头、暂停栈一定还原（`PauseGame/ResumeGame` 本身是计数栈，退出时必须配对调用）。

## 4. 演出脚本：JSON 资源格式

每场演出一个文件：`clinetcsharp/data/cutscenes/<id>.json`。运行时启动时扫描该目录加载全部；GM 触发时强制重读（热重载）。

### 4.1 文件结构

```json
{
  "id": 1,
  "name": "第一章开场",
  "letterbox": true,
  "skippable": true,
  "trigger": { "map": "luoyexiang", "rect": [10, 5, 3, 3], "once": true },
  "cues": [
    { "seq": 1, "group": 0, "type": "fade", "actor": "", "params": { "dir": "out", "sec": 0.5 } }
  ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 演出 ID（与文件名一致，保存时插件校验） |
| name | string | 名称（备注用） |
| letterbox | bool | 全程是否挂电影黑边（默认 true） |
| skippable | bool | 是否允许 ESC 跳过（默认 true） |
| trigger | object/null | 触发配置；null 或缺省 = 不自动触发（仅 GM） |
| trigger.map | string | 触发地图名 |
| trigger.rect | int[4] | 触发矩形 `[x, y, w, h]`（格子坐标），玩家落格进入即触发 |
| trigger.once | bool | 是否只播一次（默认 true，配合本地进度记录） |
| cues[] | array | 演出指令列表 |

### 4.2 cue 字段

| 字段 | 类型 | 说明 |
|------|------|------|
| seq | int | 执行顺序（升序） |
| group | int | 并行组号：同 seq 内 group 相同的 cue 并行开始；编排器等待该 seq 的全部 cue 完成后才进入下一 seq |
| type | string | 指令类型，见 §4.3 |
| actor | string | 目标演员（§3.2 寻址），无演员语义时为空串 |
| params | object | 参数，schema 按 type 定义（§4.3） |

并行语义用 `seq + group` 两个字段表达，不引入嵌套结构。编辑器插件以"时间轴行"的形式呈现 seq/group，作者不需要手写数字（插件自动维护）。

### 4.3 指令类型（第一期）

| type | actor | params | 说明 |
|------|-------|--------|------|
| `wait` | — | `{sec: 1.0}` | 延时 |
| `dialogue` | 可选（说话人） | `{speaker:"望月仙君", content:"…"}` | 走 StoryPanel 的单行对白；speaker 空=旁白。等待玩家回车翻页 |
| `bubble` | 必填 | `{text:"!", sec:2.0}` | 头顶气泡。`text` 支持表情符号（`!` `?` `…` 等约定符号，放大显示，零美术资产）和短句 |
| `move` | 必填 | `{x:10, y:5, sec:1.5}` | 走到指定格，时长可选（缺省按默认速度）。等待移动完成 |
| `face` | 必填 | `{dir:"down"}` | 朝向 |
| `camera_focus` | 可选 | `{x,y 或 用 actor, zoom:1.5, sec:1.0}` | 镜头平滑移到目标；不带坐标则聚焦 actor |
| `camera_set` | — | `{x:10, y:5, zoom:1.5}` | 镜头瞬移到指定格（无 sec，立即生效），zoom 可选；用于幕布后预置机位 |
| `camera_reset` | — | `{sec:1.0}` | 镜头回归玩家（平滑） |
| `camera_shake` | — | `{strength:8, sec:0.4}` | 震动（需在 CameraController 新增） |
| `fade` | — | `{dir:"out"/"in", sec:0.8}` | 黑场，复用 ScreenTransition |
| `actor_enter` | `actor`(id) + `x,y` | `{actor:"1", x:10, y:5}` | 让演员 id 登场到指定格子（§5.5 解析外观/名字） |
| `actor_leave` | `actor`(id) | `{actor:"1"}` | 让演员 id 退场消失 |
| `sfx` / `bgm` | — | `{name:"…"}` | 第一期仅解析记录日志，不实际播放（无音频资产与 AudioManager），第二期接音频系统后生效 |

### 4.4 示例（第一章开场片段，`data/cutscenes/1.json`）

```json
{
  "id": 1,
  "name": "第一章开场",
  "letterbox": true,
  "skippable": true,
  "trigger": null,
  "actors": [
    { "id": 1, "type": 2, "monsterConfigId": 1001 }
  ],
  "cues": [
    { "seq": 1, "group": 0, "type": "fade",         "actor": "",  "params": { "dir": "out", "sec": 0.5 } },
    { "seq": 2, "group": 0, "type": "actor_enter",  "actor": "1", "params": { "x": 12, "y": 8 } },
    { "seq": 3, "group": 0, "type": "camera_focus", "actor": "1",  "params": { "zoom": 1.5, "sec": 0.5 } },
    { "seq": 4, "group": 0, "type": "fade",         "actor": "",  "params": { "dir": "in", "sec": 0.5 } },
    { "seq": 5, "group": 0, "type": "bubble",       "actor": "1",  "params": { "text": "!", "sec": 1.5 } },
    { "seq": 6, "group": 0, "type": "move",         "actor": "1",  "params": { "x": 8, "y": 8, "sec": 1.2 } },
    { "seq": 6, "group": 1, "type": "dialogue",     "actor": "1",  "params": { "content": "史莱姆挡住了去路！" } },
    { "seq": 7, "group": 0, "type": "camera_reset", "actor": "",  "params": { "sec": 0.8 } }
  ]
}
```

- seq=6 两条 group 不同：演员 1 先走位，走完播对白——如需"边走边说"则把两条填成同 group。
- **演员表（actors，§4.1）**：演出开头声明全部演员 `{ id, type, monsterConfigId }`，id 在演出内递增、分配后固定、删除不回填；演员默认不在场，落点由 `actor_enter` 决定，后续 cue 用整数 id 引用（不再用 `actor:别名`）。
- **fade 是幕布**：fade out 之后、fade in 之前的 cue 玩家全部看不见。幕布后只放"布置类"cue（actor_enter、camera_focus 预置机位、actor_leave），可视类 cue（dialogue/bubble/需要观看的 move）必须放在 fade in 之后。运行时在黑幕中执行 dialogue/bubble 会 `PushWarning` 提示脚本顺序错误。

## 5. 编辑器插件（`clinetcsharp/addons/cutscene_editor/`）

可视化编排工具，Godot 编辑器插件形态（`EditorPlugin` + 底部/侧边 Dock），实现时对照项目已有 `*_editor` 插件。

### 5.1 功能（第一期）

- **演出管理**：扫描 `data/cutscenes/*.json` 列出全部演出；新建/重命名/删除/保存。
- **cue 时间轴**：按 `seq/group` 排序的行列表；添加/删除/上移/下移/复制 cue；同 group 的行在 UI 上并排或同色标记，直观呈现并行关系。
  - 实现约定：插件把每个 (seq, group) 执行组称为一个"步骤"（步骤内并行、步骤间串行），任何结构改动后统一重排为 `seq=步骤号、group=0`；上移/下移/复制以整组步骤为单位，"并入上一步/脱离并行组"负责并行关系的合并与拆分，作者不手写数字。
- **参数表单**：选中 cue 后按 type 动态生成表单（每种 cue 一个固定字段集，禁止手填 JSON）；坐标类字段（`x/y`、`rect`）带"从地图拾取"按钮。
- **地图视图**：SubViewport 渲染目标地图（复用/对照地图编辑器插件的地图加载方式），支持：
  - 点击格子拾取坐标填入当前 cue 字段；
  - 框选矩形设置 `trigger.rect`；
  - 显示 `actor_enter` 登场落点标记与 `move` 走位路径折线（静态示意）。
- **演员表行**：在演出下拉栏与 cue 时间轴之间放一行"演员表 (N)"入口，点击展开成编辑面板（只展开不收起）；面板内列出每个演员的 id / 类型下拉（玩家·怪物）/ 怪物配置下拉（仅怪物）/ 删除按钮，底部"添加演员"按钮自动分配下一个 id。cue 表单的 actor 字段（move/face/bubble/actor_enter/actor_leave/camera_focus/dialogue）均为下拉，列出演员表 id + 名字/类型。
- **校验与保存**：保存时校验（id 与文件名一致、演员先 actor_enter 后引用、坐标在地图范围内、type 合法、怪物演员必填 monsterConfigId），错误在行内标红。

### 5.2 硬性实现约束（来自 AGENTS.md 插件规则，必须遵守）

- 所有被插件复用的运行时脚本必须加 `[Tool]` 特性；`_Ready/_Process` 中的运行时副作用用 `Engine.IsEditorHint()` 守卫。
- SubViewport **禁止** `Stretch=true + StretchShrink=1`；监听容器 `Resized` 信号后手动同步 `SubViewport.Size`。
- 插件只读写 `data/cutscenes/*.json`，不碰其他任何数据；与运行时共享同一份 JSON 读写/校验代码（放在 `Scripts/Cutscene/` 下的 `CutsceneScriptIO.cs`，插件与运行时都调用）。

### 5.3 与游戏内回放的分工

插件负责"编"和**模拟预览**（§5.4），游戏内 GM 命令负责**真实回放**：插件保存 JSON → 游戏里 `cutscene,<id>` 热重载回放真实效果（StoryPanel 打字机、暂停、真实气泡样式只有运行时才有）。

### 5.4 模拟预览（2026-07-22 追加）

在地图视口内按真实时序把整场演出"演"出来，验证节奏、走位、镜头构图、幕布顺序。

- **播放控制**：播放/暂停/停止/单步（按步骤=执行组前进）；时间轴高亮当前执行的步骤。
- **镜头即视图**：`camera_focus`/`camera_reset`/`camera_shake` 直接驱动地图视图的 Camera2D（平移/缩放/震动），所见即游戏镜头构图。镜头"家"位置（camera_reset 目标）= `trigger.rect` 中心，未配触发器则取地图中心。
- **演员令牌**：`actor_enter`/`move`/`face`/`actor_leave` 用带名字与方向箭头的色块令牌按真实时长 Tween 表现；`bubble` 在令牌头顶显示文字/符号到时消失。
- **幕布与黑边**：`fade` 在视口上叠黑色渐变；`letterbox=true` 全程叠上下黑边。
- **对白**：`dialogue` 在视口底部出文字条（说话人+内容），点击/空格继续（模拟运行时回车翻页）。
- **限制**：演出演员全部是本地假人（玩家用预设外观、怪物按 `monster_config.json`），不涉及服务器同步的真实实体，故预览中均可正常显示；`sfx`/`bgm` 只记日志。真实游戏内回放以游戏内效果为准。
- 预览不改变正在编辑的脚本数据；预览期间时间轴/表单只读（防串改）。

### 5.5 预览渲染与运行时一致 + 表来源角色（2026-07-22 追加）

**地图预览与运行时一致**：视口内直接复用运行时渲染链路，不再用 CPU 色块自绘：

- SubViewport 内 `new GridManager { SkipAutoLoad = true }`（GridSize 保持运行时默认 **111**；编辑器原 48 常量废弃，令牌/拾取/叠加全部按 111 换算），地形/网格线/图外灰全部由 `GridShaderOverlay` GPU shader 渲染，与游戏画面一致。该编辑器复用路径与 `addons/map_editor_editor` 相同（`MapEditorBottomPanel.cs:212`）。
- 装饰物用真实 `MapDecoration` 节点渲染：配置经编辑器安全路径加载（`ProfileConfigIO.LoadFromFile()` + `DecorationConfigUtil.LoadFromProfiles()`），逐格子 `MapDecoration.SetupFromProfile()`，多格建筑按占地去重——同 `MapEditorBottomPanel.RefreshDecorations` 模式。
- `CutsceneMapRenderer` 退化为纯叠加层：只画触发区/spawn 落点/move 折线/选中高亮/框选预览，不再画地形与网格。
- 切地图后相机默认 zoom≈0.5（视野与原 48@zoom1 相当）。

**camera_set cue**：瞬移设置机位（`{x, y, zoom?}`），无 tween、立即生效；与 `camera_focus`（平滑）互补，主要服务于 fade 幕布后预置机位。运行时直接赋值 `Camera2D.GlobalPosition/Zoom`，预览同样直设视图相机。

**演员表（actors 数组，§4.1）**：演出开头声明演员，后续 cue 用整数 id 引用（不再用 `actor:别名`）。每个演员 `{ id, type, monsterConfigId }`：
- `id`：演出内递增、分配后固定、删除不回填（删除不影响已有引用）。
- `type`：`1=玩家`、`2=怪物`，`3=NPC` 预留未实现。
- 演员**默认不在场**，落点由 `actor_enter` cue 决定；保留"中途登场 / 提前退场"（`actor_leave`）。

**外观与名字来源（由共享静态类 `CutsceneActorCatalog` 解析，编辑器安全、不依赖运行时单例）**：
- 玩家（type=1）：单一预设外观（`EntityStyleConfig.CreateNpcDefault`，蓝色系），名字固定"玩家"。
- 怪物（type=2）：名字取自 `monster_config.json` 的 `MonsterDef.Name`；外观当前统一走 `EntityStyleConfig.CreateMonsterDefault`（红色系），与真实怪物同款视觉管线。
  （注：`MonsterDef.UiConfigId → EntityStyleConfig` 的精细化外观映射依赖运行时 `MonsterManager` 单例，编辑器内取不到，故此处用默认样式；`monster_config.json` 中 `UiConfigId` 目前多为默认值 1，需差异化时直接在该表加怪物配置即可。）
- **已移除旧的 `source` 参数与 `preset:player`/`monster:<id>`/`npc:<id>` 来源体系**（含 `servercsharp` 的 `common_tbnpc.json` 跨工程依赖）；旧 `spawn_actor`/`despawn_actor` cue 已废弃。
- 编辑器参数表单：`actor_enter`/`actor_leave`/`move`/`face`/`bubble`/`camera_focus`/`dialogue` 的 actor 字段是下拉（列出演员表 id + 名字/类型）；`dialogue` 的 `speaker` 填演员 id 自动带出名字，也可直接填显示名。

### 5.6 布局自适应与游戏画面比例（2026-07-22 追加）

- Dock 根容器用 FullRect 锚点充满 EditorDock 区域：`CutsceneDock` 是普通 `Control` 而非容器，子节点的 `SizeFlags` 不生效，不锚定会让整个三列布局停留在最小尺寸，专注模式下面板右侧/底部出现大片死黑区。
- 三列只给紧凑的固定最小宽度（时间轴 400 / 参数 360 / 地图视口下限 320×180），列不随窗口拉伸；多余横向空间全部留给第 3 列。
- 地图视口外包 `AspectRatioContainer`（FIT + 水平居中 / 垂直顶对齐），`Ratio` 读取 `project.godot` 的 `display/window/size`（当前 1280×720 → 16:9）：视口始终按游戏画面宽高比等比缩放，放不下的空间留边而不是拉伸视口，保证插件预览构图与游戏内镜头构图一致。`SubViewport.Size` 仍走既有的容器 `Resized` 手动同步（§5.2 约束不变）。

## 7. 触发与进度

- **GM 手动触发**：`cutscene,<id>`，用于制作与验收；不受进度限制、不看触发区域，可重复播。
- **区域自动触发**（第一期）：`CutsceneTrigger` 在玩家落格后检查当前地图已配置的演出，命中 `trigger.rect` 且（`trigger.once=true` 时）未看过 → 自动播放。纯客户端本地检测，不动服务器。
- **进度记录**：看过的演出 ID 写入 `user://cutscene_progress.cfg`；`trigger.once` 的演出凭此只播一次。演出被跳过也计为"已看"（避免玩家被同一演出反复拦截）。
- **互斥**：一场演出播放期间不再触发其他演出；触发检查在演出结束后恢复。
- 进度同步到服务器：第二期。

## 9. 验收标准（第一期）

1. GM 命令 `cutscene,1` 能完整播放 §4.4 示例演出：黑场 → 假人出现 → 镜头推近 → 气泡 → 走位+对白 → 镜头回归 → 黑场恢复。
2. 演出期间：HUD 隐藏、玩家无法操作、世界暂停；演出相关节点正常工作。
3. 中途 ESC 跳过后：镜头、HUD、输入、暂停栈完全还原，无残留气泡/黑边/假人。
4. 编辑闭环：在插件里新建/修改演出并保存 → 游戏内 GM 触发即生效，**无需重启客户端、无需改代码、不经过 Luban**。
5. 插件能力：cue 增删改排序、按类型出参数表单、地图视图点击拾取坐标、框选触发区，保存时校验能拦住非法数据。
6. 区域触发：配置 `trigger` 的演出，玩家踩入区域自动播放一次；离开后重进不再播；GM 触发不受此限。
7. 故意配错（演员名不存在 / 目标格非法 / JSON 改坏）：屏幕弹出明确错误提示并安全恢复，无卡死、无残留。
8. 模拟预览（§5.4）：在插件里对 §4.4 示例演出点"播放"，地图视口内按真实时序完整播完——幕布 → 令牌出现 → 镜头推近 → 气泡 → 走位+对白（点击/空格翻页）→ 镜头回归；播放/暂停/停止/单步可用，时间轴高亮当前步骤；播放期间时间轴/表单编辑被拦截并有状态栏提示；停止后视图机位还原、无令牌/幕布/黑边残留。
