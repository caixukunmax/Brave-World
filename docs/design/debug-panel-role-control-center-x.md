# 调试面板角色附着控件 X 轴居中方案

> 状态：已确认
> 日期：2026-04-29
> 范围：`clinetcsharp/` 玩家、怪物、NPC 身上的附着控件

## 1. 背景

当前调试面板里的“居中”能力只覆盖了部分标签文本，而且不同角色类型、不同控件的 X 轴定位基准并不一致：

1. 玩家 4 行文字使用 `RichTextLabel` 容器布局，已有一组 `LabelAutoCenterX`
2. 怪物 / NPC 4 行文字使用 `EntityBase.DrawLabels()`，每行已有 `LabelCenterX`
3. 血条、MP 条、施法条、等级徽章、NPC 交互面板等仍然主要依赖单独的 X 偏移值

这导致“X 轴居中”在用户视角下不是统一能力，而是若干零散特例。

## 2. 用户需求

用户要求：

1. 只要是角色身上的控件，都要支持 X 轴居中
2. 角色范围包括：玩家、怪物、NPC
3. “居中”的语义是：**控件的中心点 X 与当前地图格子的中心点 X 对齐**
4. 开启居中后，不能再继续手动调整该控件的 X 值

## 3. 表象与根因

### 3.1 表象

- 调试面板里同样叫“X 偏移”或“居中”的控件，实际行为不一致
- 有的控件是对文字自身居中，有的控件是用固定 X 偏移，有的控件根本没有居中开关
- 用户无法形成统一心智模型

### 3.2 根因

根因不是缺一个开关，而是缺少统一的 **X 轴锚点模型**。

在当前客户端实现里，玩家、怪物、NPC 的 `Node2D.Position` 本身已经通过 `UiUtils.GridToWorld(...)` 对齐到地图格子中心，因此：

- “格子中心”并不需要额外计算成另一套世界坐标
- 角色附着控件只要以实体原点为 X 基准，就等价于“对齐当前格子中心”

因此真正需要统一的是：**每个附着控件是否锁定到实体原点 X**，而不是分别给每个控件做临时补丁。

## 4. 目标

本次需求的目标是：

1. 为所有有 X 轴定位能力的角色附着控件引入统一的 `CenterX` 规则
2. `CenterX = true` 时，控件中心 X 锁定到角色原点 X
3. `CenterX = true` 时，对应的调试面板 X 控件禁用，不能继续手动调整
4. 保持已有 Y 偏移、尺寸、颜色等调试能力不变
5. 保持现有配置文件兼容，旧配置默认能继续读取

## 5. 非目标

本轮不做以下事项：

1. 不重构角色绘制系统的整体架构
2. 不统一所有 UI 的锚点概念到通用布局系统
3. 不改变动作栏现有“天然水平居中”的表现，只确认它继续保持不可调 X
4. 不对与角色无关的 UI 控件增加居中能力

## 6. 统一规则

### 6.1 核心模型

对所有角色附着控件，统一引入以下语义：

- `CenterX = true`
  - 控件中心 X 对齐角色原点 X
  - 角色原点 X 等价于当前地图格子中心 X
  - 手动 X 值不再参与布局，或被归零处理
  - 调试面板里的对应 X 控件禁用
- `CenterX = false`
  - 使用手动 X 偏移
  - 偏移基准仍然是角色原点 X

### 6.2 行为要求

为避免“表面禁用、底层仍有脏值”的问题，本次实现要求同时满足：

1. UI 层：开启居中后，X 滑块不可编辑
2. 数据层：开启居中后，对应 X 值不再影响最终布局
3. 渲染层：布局逻辑显式判断 `CenterX`

## 7. 覆盖范围

### 7.1 玩家

需要支持 `CenterX` 的控件：

1. 4 行标签文本
2. 血条
3. MP 条
4. 施法条
5. 等级徽章

说明：

- 动作栏目前由 `EntityDrawUtils.DrawActionBar(...)` 固定按宽度居中绘制，没有独立 X 滑块，本轮保持“天然居中、不可调 X”即可
- 玩家现有的 `LabelAutoCenterX` 是整组标签级别的开关，本轮调整为与怪物 / NPC 一致的“每行独立 CenterX”

### 7.2 怪物

需要支持 `CenterX` 的控件：

1. 4 行标签文本
2. 血条
3. MP 条

说明：

- 动作栏继续保持天然水平居中
- 标签现有已有每行 `LabelCenterX`，本次只需把条形控件补齐

### 7.3 NPC

需要支持 `CenterX` 的控件：

1. 4 行标签文本
2. 血条
3. MP 条
4. 交互面板

说明：

- 交互面板当前区分 A / B 两种站位方向，本轮为 A-X / B-X 分别增加居中语义
- A / B 的 Y 偏移保持现有语义不变

## 8. 数据模型调整

### 8.1 实体样式配置

在 `EntityStyleConfig` 中新增以下布尔配置：

1. `HpBarCenterX`
2. `MpBarCenterX`
3. `InteractMenuCenterX_A`
4. `InteractMenuCenterX_B`

标签现有的 `LabelCenterX[]` 继续复用。

### 8.2 玩家专有配置

玩家因拥有独有控件，需要额外增加：

1. `CastBarCenterX`
2. `LevelBadgeCenterX`

玩家标签现有 `LabelAutoCenterX` 需要收口为每行 `CenterX[]`，避免继续维护一套独立概念。

## 9. 实现策略

### 9.1 方案选型

采用“统一 CenterX 模型”，不采用“每个控件各自补 if”方案。

原因：

1. 用户需求已经明确要求“所有角色附着控件”统一语义
2. 当前分散状态已经造成玩家 / 怪物 / NPC 行为不一致
3. 继续零散修补会让配置字段和调试 UI 越来越难维护

### 9.2 代码结构

新增一个纯规则 helper，负责统一计算：

1. 当 `CenterX=true` 时应使用的最终 X
2. 当 `CenterX=true` 时调试 UI 是否应该禁用 X 滑块

这样可以先写单元测试，再把玩家、怪物、NPC 接入同一规则，而不是把条件判断复制到多处。

### 9.3 玩家标签兼容策略

玩家标签目前使用 `Vector2[] _labelOffsets` + `LabelAutoCenterX`。

本次改造后：

1. 保留现有标签偏移数据结构，避免大改 `RichTextLabel` 系统
2. 增加每行 `bool[] _labelCenterX`
3. `UpdateAllLabelPositions()` 改为按每行 `CenterX` 计算 X
4. 旧配置若只有 `label_auto_center_x`，则加载时把它映射到全部标签行的 `CenterX`

## 10. 配置兼容

### 10.1 必须兼容的旧字段

1. 玩家旧标签自动居中字段
2. 怪物 / NPC 已有 `label_center_x_*`
3. 所有现有 `*_offset_x` 字段

### 10.2 兼容要求

1. 旧配置文件不报错
2. 旧配置没有新增布尔字段时，沿用当前默认值
3. 旧玩家全局自动居中配置自动迁移到逐行标签 CenterX
4. 新增布尔字段采用保守默认值，尽量保持用户当前视觉结果

## 11. 测试策略

### 11.1 单元测试

新增客户端测试项目，先对纯规则 helper 做失败测试，覆盖：

1. `CenterX=true` 时最终 X 固定为中心基准
2. `CenterX=false` 时最终 X 保留手动偏移
3. `CenterX=true` 时 UI 应返回“不可编辑”

### 11.2 构建验证

至少验证：

1. `dotnet test` 客户端新增测试项目通过
2. `clinetcsharp` 客户端项目编译通过

### 11.3 功能验证

手工验证以下场景：

1. 玩家 / 怪物 / NPC 标签开启居中后不能调 X
2. 玩家血条 / MP 条 / 施法条 / 等级徽章开启居中后不能调 X
3. 怪物 / NPC 血条、MP 条开启居中后不能调 X
4. NPC 交互面板 A / B 两种站位下，开启居中后不能调对应 X

## 12. 风险与防御

### 12.1 风险

1. 玩家标签旧配置迁移可能导致首帧表现变化
2. NPC 交互面板当前是菜单节点挂在 NPC 下，A / B 站位居中规则若处理不当会改变原有左右展开习惯
3. 调试面板新增开关较多，若 UI 同步不完整，容易出现滑块显示值和实际状态不一致

### 12.2 防御措施

1. 先抽纯规则 helper，并用测试固定语义
2. 所有 `CenterX` 开关切换时统一调用“更新滑块可编辑性”的方法
3. 配置读取时显式兼容旧字段，不做静默覆盖
