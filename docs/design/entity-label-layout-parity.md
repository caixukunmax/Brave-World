# 玩家/野怪/NPC 标签布局一致性

## 1. 背景

当前玩家、野怪、NPC 虽然都显示为格子内的标准方块，但标签布局并没有完全使用同一套语义：

- 野怪 / NPC 使用 `EntityBase` 的四行标签基线布局
- 玩家仍保留旧的 `Player` 私有标签偏移链路
- 玩家自动字号曾使用独立公式，和野怪 / NPC 的默认字号推导不一致

这会导致一个直接问题：

- 调试面板里输入一样的标签参数
- 玩家和野怪看起来却不是同一种效果

用户感知上就会变成“方块好像错位了”“同样参数没有同样表现”。

## 2. 目标

统一玩家、野怪、NPC 的标签布局语义：

1. 四行标签都基于同一套基线公式计算
2. 自动字号也基于同一套默认公式计算
3. `X偏移 / Y偏移 / 居中` 的含义在三类实体上完全一致
4. 相同参数必须得到相同表现
5. 实体本体继续保持标准正方形渲染，不因标签链路不同而产生视觉错觉

## 3. 根因

根因不是格子不是正方形，也不是玩家和野怪本体用了不同的方块绘制逻辑。

本体渲染上，玩家、野怪、NPC 都共用：

- `EntityBase.VisualOuterSize`
- `EntityBase.VisualSize`
- `RenderComponents.AppearanceComponent`
- `EntityDrawUtils.DrawBody(...)`

真正分叉的是标签布局：

- 野怪 / NPC：`LabelYOffsets` 是“基于四行统一基线的相对偏移”
- 玩家：旧链路里的 `_labelOffsets` 曾按“绝对摆放位置”使用
- 玩家：`font size = 0` 时走的是私有自动字号公式

因此同样的 `Y偏移=0`：

- 野怪表示“落在这一行的标准基线上”
- 玩家却可能表示“落在节点局部坐标原点附近”

这就是“同参数不同表现”的根因。
即使偏移语义统一，如果自动字号公式不统一，文本密度和视觉重心仍然会不同。

## 4. 方案

### 4.1 统一四行标签基线算法

新增共享标签布局 helper，统一计算：

- 基础字号
- 行高
- 四行总高度
- 每一行的基线中心点

玩家、野怪、NPC 都使用这套 helper。

### 4.2 玩家旧偏移语义收口

玩家保留旧的数据结构以兼容调试拖拽与旧入口，但布局含义改为：

- `X偏移`：相对于统一基线的水平偏移
- `Y偏移`：相对于统一基线的垂直偏移
- `CenterX=true`：该行文本中心对齐到实体原点 X

也就是说，玩家不再把 `_labelOffsets` 当成绝对位置。

## 5. 非目标

本轮不改以下内容：

1. 不改玩家/怪物/NPC 的本体方块绘制公式
2. 不把等级角标并入四行标签
3. 不调整格子世界坐标换算公式

## 5.1 诊断辅助

为了区分“本体真的偏了”还是“标签/条形造成视觉错觉”，需要提供一套全实体共用的诊断 overlay：

1. 当前格子外框
2. 实体外轮廓框
3. 实体内部绘制框
4. 中心十字

该 overlay 必须对玩家、野怪、NPC 使用同一套绘制规则，不能再只给玩家单独画调试辅助线。

## 6. 验证标准

修复后应满足：

1. 玩家与野怪设置相同 `appearance + labels` 参数时，四行文本布局表现一致
2. `X偏移 / Y偏移 / 居中` 在玩家与野怪上的结果一致
3. NPC 因为已经走通用链路，表现继续保持与野怪一致
