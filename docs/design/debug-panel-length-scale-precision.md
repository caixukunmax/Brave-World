# 调试面板长度比例唯一控制源方案

> 状态：已确认  
> 日期：2026-05-01  
> 范围：`clinetcsharp/` 调试面板中玩家、怪物、NPC 的角色附着条形控件

## 1. 背景

调试面板里部分条形控件同时暴露了“长度”和“长度比例”。这会造成两个问题：

1. 同一个 `LengthScale` 在不同 `GridSize` 下会算出不同长度，这是正常行为；如果 UI 同时允许编辑“长度”，用户会误以为两者都是独立真相源。
2. 保存配置时如果同时保存长度和比例，后续加载、切换格子大小、切换角色类型时容易出现冲突。

用户已明确要求：**只能有一个唯一控制源，使用长度比例；保存时不保存长度，长度必须靠比例计算出来；所有角色一致。**

## 2. 目标

1. 所有角色附着条形控件只把“长度比例”作为可编辑控制源。
2. “长度”不再作为可编辑配置项；如果 UI 仍展示长度，只能是只读计算结果。
3. 保存配置时不写入任何 `length` 字段，只保存 `length_scale`。
4. 加载配置时优先读取 `length_scale`，长度由 `GridSize × length_scale` 计算。
5. 所有“长度比例”滑条支持更精确调节：步进 `0.001`，显示三位小数。
6. 玩家、怪物、NPC 规则一致，避免同类控件行为分裂。

## 3. 非目标

1. 不新增“直接改长度”的滑条或输入框。
2. 不把长度作为可持久化字段。
3. 不改变高度、偏移、填充、颜色等无关控制项语义。
4. 不重构整个调试面板，只针对长度/长度比例冲突做收口。

## 4. 统一规则

### 4.1 唯一真相源

条形控件长度统一遵循：

```text
Length = Clamp(GridSize × LengthScale, min, max)
```

其中：

- `LengthScale` 是唯一可编辑、可保存的值。
- `Length` 是运行时计算值。
- UI 不允许通过编辑 `Length` 反向改写 `LengthScale`。

### 4.2 调试面板展示

对每个有长度控制的条形控件：

1. 保留“长度比例”滑条。
2. 将比例滑条步进改为 `0.001`。
3. 比例文本显示三位小数，例如 `0.721`。
4. 原有“长度”滑条必须取消可编辑能力；本轮删除可编辑滑条，只保留“长度比例”控制，避免双真相源。

### 4.3 保存与加载

新保存规则：

- 只保存 `*_length_scale`。
- 不保存 `*_length`。

旧配置处理：

- 如果旧配置存在 `length_scale`，直接使用。
- 如果旧配置存在旧 `length`，本次不做兼容换算；保存时必须删除旧 `length` 字段。
- 如果旧配置只有旧 `length` 而没有 `length_scale`，使用当前默认 `length_scale`。

## 5. 覆盖范围

### 5.1 玩家

需要应用统一规则的控件：

1. 血条长度比例
2. MP 条长度比例
3. 施法条长度比例

玩家当前已有部分“长度”滑条，本次删除这些可编辑长度滑条，避免与比例冲突。

### 5.2 怪物

需要应用统一规则的控件：

1. 血条长度比例
2. MP 条长度比例

怪物不新增直接长度编辑入口。

### 5.3 NPC

需要应用统一规则的控件：

1. 血条长度比例
2. MP 条长度比例

NPC 与怪物保持一致。

## 6. 实现策略

1. 新增或扩展纯规则 helper，用于统一长度比例精度：
   - 推荐保留现有 `DebugPanelSliderValueFormatter.Format(value, step)`。
   - 将比例滑条的 `Step` 设为 `0.001` 后，formatter 自动显示三位小数。
2. 调整玩家、怪物、NPC tab：
   - 所有长度比例滑条 `Step = 0.001`。
   - 所有比例文本使用 `DebugPanelSliderValueFormatter.Format(value, slider.Step)`。
   - 删除“长度”编辑滑条。
3. 调整保存逻辑：
   - 玩家不再保存 `healthbar.length`、`mpbar.length`、`castbar.length`。
   - 怪物和 NPC 继续只保存比例字段。
4. 调整加载与清理逻辑：
   - 只读取 `length_scale`。
   - 不读取旧 `length`。
   - 保存前清理旧 `length` 字段，避免配置文件继续残留双真相源。

## 7. 测试策略

1. 单元测试：
   - `DebugPanelSliderValueFormatter.Format(0.721, 0.001)` 输出 `0.721`。
   - `Step = 0.001` 的值不会被两位小数截断。
2. 构建验证：
   - 运行客户端测试项目。
   - 运行客户端编译。
3. 手工验证：
   - 玩家、怪物、NPC 的血条/MP 条都只能通过长度比例调节。
   - 玩家施法条也只通过长度比例调节。
   - 保存配置后文件中不再出现条形控件的直接 `length` 持久化字段。
   - 改变格子大小后，长度随比例重新计算，没有长度/比例冲突。

## 8. 风险与约束

1. 删除玩家旧“长度”滑条会改变调试面板 UI，但这是消除双真相源的必要变更。
2. 旧 `length` 字段必须在保存时清理；视觉效果以 `length_scale` 为准。
3. 实现时必须继续保持玩家、怪物、NPC 样式隔离，禁止玩家 tab 写怪物配置，禁止怪物 tab 写玩家配置。
