# 战斗系统设计稿（Combat System Design）

> 版本：V0.6
> 状态：已重构（ATB → 纯 CD 即时制）
> 更新：§6-§7 改为双向网状关系；§2.2 先手攻击改为施法提速；新增 §10 怪物领地机制

---

## 1. 设计目标

构建一套**"碰撞触发 + 大地图内纯 CD 即时战斗"**系统：

- **低门槛**：玩家控制移动 + 手动点击技能，怪物自动按 CD 释放技能。
- **高策略**：通过走位（卡距离、拉扯、风筝）直接影响战斗结果。
- **强反馈**：碰撞即开战，节奏明快，没有传统"切屏读条"的顿挫感。
- **真实感**：战斗随时可进可退，大地图上没有"安全气泡"，第三方可以随时被卷入。

---

## 2. 战斗触发机制

> **碰撞检测的移动流程详见 [`movement-system.md`](../movement/movement-system.md) §4.2（碰撞性移动）和 §5.2（怪物碰撞）。**
> 本节仅描述战斗触发的业务规则。

### 2.1 主动碰撞（Initiative Collision）

- **大地图上所有角色（玩家与玩家、玩家与怪物、怪物与怪物）均不能占据同一格子**。
- **角色移向敌方占据的格子时，先移动 30%，在 30% 检查点检测碰撞**（客户端检测 + 服务端校验），确认后弹回原位再触发战斗。
- 战斗不切换场景、不加载副本，直接在当前大地图坐标上进入战斗状态。
- **碰撞与先手规则**：
  - 若碰撞双方**均未处于战斗状态**：
    - **玩家主动撞向野怪** → 玩家获得**先手攻击权**（First Strike）。
    - **怪物主动撞向玩家** → **不触发先手**，双方正常进入战斗。
    - 野怪受攻击后，正式进入战斗。
  - 若有一方**已在战斗中**：
    - **不免疫碰撞**：第三方路过时仍可能因碰撞、技能溅射等原因被卷入新的战斗关系。
    - **不触发先手**：先手攻击权仅在碰撞双方此前均未建立过任何战斗关系时触发。若目标已在战斗中，仅建立新的双向战斗关系，不享受先手提速。
  - **PVP**：当前版本玩家之间碰撞仅阻止移动，不触发战斗、不建立战斗关系（详见 §11）。

### 2.2 先手攻击（First Strike）

- 先手方在碰撞后的**第一个技能**获得**施法提速**（Cast Time 减少）。
- 提速幅度由玩家属性 **`FirstStrikeHaste`** 决定（单位：毫秒或百分比，由策划配置）。
- 该效果**仅对碰撞后的第一个技能生效**，且仅在碰撞双方此前均未建立过战斗关系时触发。
- 随后双方正式进入战斗，按各自技能 CD 独立行动。

> **示例**：玩家 A（FirstStrikeHaste = 50）撞向野怪 M。A 释放的第一个技能原 CastTime = 500ms，提速 50% 后实际只需 250ms。第二个技能起恢复正常。

### 2.3 第三方卷入（真实世界规则）

- 大地图上**不存在战斗隔离区**。
- 第三方角色或怪物如果：
  - **主动碰撞**了正在战斗中的角色/怪物；
  - **被范围技能波及**并造成了伤害；
- 则该第三方会被纳入战斗关系，开始独立计算自己的技能 CD。
- **AOE 命中即建立关系**：范围技能对未建立关系的敌人造成伤害时，**立即建立双向战斗关系**，敌人会主动追击。
- 战斗关系是**双向网状结构**：每个实体维护自己的敌人列表。A 与 B 在战斗，B 与 C 在战斗，A 和 C 互不影响各自的脱战判定。

## 3. 战斗属性（Combat Attributes）

| 属性 | 作用说明 |
|------|----------|
| **血量（HP）** | 生命值为 0 时角色战败/撤退。 |
| **护甲（Armor）** | 物理减伤层（具体公式待技术设计时确定）。 |
| **蓝条（MP）** | 释放技能消耗的资源，普攻不消耗。 |
| **物攻（PATK）** | 影响物理伤害。 |
| **法攻（MATK）** | 影响法术伤害。 |
| **物防（PDEF）** | 降低受到的物理伤害。 |
| **法防（MDEF）** | 降低受到的法术伤害。 |
| **移动速度（Move Speed）** | 影响大地图移动速度；**战斗中移速与大地图移速一致**。 |
| **先攻加速（FirstStrikeHaste）** | 碰撞先手时，第一个技能的施法提速比例（取值 **0~100**，如 50 表示提速 50%，即 CastTime × 0.5）。 |
| **迅捷（Agility）** | 当前版本暂不影响战斗节奏（后续可赋予减 CD、加移速等作用）。 |

## 4. 核心战斗机制：纯 CD 即时制

### 4.1 技能释放规则

- **玩家可以随时手动释放技能**（只要技能不在 CD 中、在范围内、有足够 MP）。
- **怪物按技能 CD 自动释放技能**，CD 好的技能由 AI 自动选择并释放。
- **蓄力期间角色不可移动**（若技能配置了移动打断），移动请求会被服务端拒绝。
- **普通攻击被抽象为一个"零消耗、短冷却的技能"**，所有 AI 判定逻辑统一走"技能选择"流程。

### 4.2 技能冷却（CD）

- 每个技能有独立的冷却时间，释放后进入 CD。
- 怪物 AI 每帧检查是否有 CD 好的技能，有则自动释放。
- 玩家通过 SkillBar 点击主动释放技能，客户端本地做 CD 预判减少无效请求。

### 4.3 战斗节奏

- 战斗节奏完全由技能 CD 决定，不再有"排队等待"的感觉。

## 5. 战斗中的角色控制与 AI

### 5.1 玩家可控 vs 自动战斗

- **玩家可以持续控制角色在大地图上移动**（移速 = 大地图移速），但蓄力期间不可移动。
- **玩家点击 SkillBar 上的技能按钮即可释放**（受 CD/MP/范围限制）。
  - **主动点击**的单体技能：若优先目标不在射程内，角色**自动寻路**移动到射程内再释放。
  - **自动战斗**触发的技能：
    - 若存在**优先攻击目标**且目标在射程内，优先以优先攻击目标为主目标释放。
    - 若优先攻击目标不在射程内或不存在优先攻击目标，按 §6.2 优先级表选择**普通攻击目标**释放。
    - 若所选目标不在射程内，**本次不执行任何动作**，等待下一次 CD 检查（不寻路）。
- **怪物按 CD 自动释放技能**，AI 只在"当前位置满足施法距离"且"不在冷却中"的技能中选择。
- 玩家通过走位 + 手动技能释放来指挥战斗。

### 5.2 距离尊重原则（Range Respect）

> **AI 不得为了释放近战技能而自动走回敌人身边。**  
> **AI 只能在"当前位置可释放"的技能中进行选择。**

- 每条技能需具备**施法距离**属性。
- AI 的决策顺序（CD 驱动）：
  1. 筛选**当前位置满足施法距离**且**不在冷却中**的技能。
  2. 从中按优先级（伤害最高 / 性价比最优）选择一项释放。
  3. 若列表为空（玩家跑太远，所有技能都打不到）：
     - 角色**本次不执行任何动作**，等待下一次 CD 检查。

## 6. 多方参战规则

### 6.1 战斗关系（网状多对多）

- 每个实体（玩家/怪物）维护一个**敌人列表**。
- 碰撞或 AOE 命中时，在**双方**的敌人列表中互相添加对方。
- **同一个角色可以同时与多个目标建立战斗关系**。
- 当该角色的某个技能 CD 好时，AI 会根据当前敌人列表中的目标，选择最优目标释放技能。
- **脱战是双向移除**：当某条关系满足脱战条件时，**双方同时**从各自的敌人列表中移除对方。任何一方满足脱战条件即可触发整条关系的断开。

> **示例场景**：
> - 玩家 A 碰撞野怪 M1 → A 的敌人列表加入 M1，M1 的敌人列表加入 A。
> - 玩家 A 又碰撞野怪 M2 → A 的敌人列表加入 M2，M2 的敌人列表加入 A。
> - A 与 M1、M2 同时处于战斗中。A 的每个技能按各自 CD 独立冷却，CD 好时由 AI 或玩家手动选择目标释放。
> - M1 和 M2 各自也分别与 A 建立战斗关系，它们各自的技能按各自 CD 独立冷却。
> - 若 A 与 M1 距离过远满足脱战条件 → **A 和 M1 同时**从对方的敌人列表中移除，双方均不再视对方为敌人。

### 6.2 目标选择优先级（统一表）

当技能 CD 就绪且存在多个合法目标时，AI 按以下优先级排序选择目标：

| 优先级 | 规则 | 说明 | 生效时机 |
|--------|------|------|----------|
| 1 | **挑衅优先（撞击）** | 最近一次主动撞击/碰撞该实体的攻击者 | **2 秒**（挑衅期） |
| 2 | **距离最近** | 在技能 CastRange 内的目标，优先选距离最近的 | 实时 |
| 3 | **血量百分比最低** | 距离相同时，优先选残血目标（收割逻辑） | 实时 |
| 4 | **累计伤害仇恨** | 对该实体造成最高累计伤害的目标 | 实时（关系级） |

- **挑衅期**：碰撞/被撞击后的 2 秒内，目标死追挑衅者（撞击者）。2 秒后按后续优先级重新评估。
- 只有位于技能 **CastRange** 内的目标才进入候选池。
- 如果候选池为空（所有目标都在射程外），则本次不释放技能，等待下一次 CD 检查。

### 6.3 攻击目标分类

#### 普通攻击目标（AI 自动选择）

- 当玩家**没有**手动设置优先攻击目标时，所有敌人皆为普通攻击目标。
- 自动战斗模式下，玩家的技能释放目标由 AI 按 §6.2 优先级表自动选择，**可以随时在不同普通攻击目标之间切换**。
- 普通攻击目标的选择是动态的，每帧按当前状态重新评估。

#### 优先攻击目标（玩家手动锁定）

- **设定方式**：
  - **主动撞击**某怪物时，该怪物设为优先攻击目标。
  - **鼠标点击**某怪物（或敌人）时，该目标设为优先攻击目标。
- **锁定特性**：有多个敌人关系时，**只有一个**敌人可以被设为优先攻击目标。优先攻击目标一旦设定，**不会**因 AI 策略而自动切换。
- **SkillBar 主动释放的单体技能**：优先以优先攻击目标为主目标；若优先攻击目标不在射程内，角色**自动寻路**到射程内再释放（详见 §5.1）。
- **优先攻击目标在以下情况清除**：
  - 玩家与该目标的战斗关系脱战；
  - 优先攻击目标死亡；
  - 玩家主动撞击或点击另一个目标（切换优先攻击目标）。
- **怪物主动撞击玩家时**：
  - 若玩家**已在战斗中**（敌人列表非空），**不自动切换**优先攻击目标。
  - 若玩家**未在战斗中**（敌人列表为空），优先攻击目标**自动设为**该怪物（只有一个敌人，无需玩家手动选择）。

### 6.4 AOE / 范围技能

- AOE 技能的目标判定**以技能配置为准**，不依赖战斗关系。
- 只要在技能的 CastRange / AOE 半径内的合法目标，都会被命中。
- **命中未建立关系的敌人时，立即建立双向战斗关系**，敌人会主动追击。
- 目标是否处于战斗关系中**不影响** AOE 的命中判定（范围技能可以命中未建立关系的敌人，且命中后即建立关系）。
- **AOE 技能的目标选择逻辑**：AOE 技能类型多样（目标型、方向型、自身范围型等），具体寻路与释放逻辑需根据技能子类型单独设计。但至少保证：**单体目标技能**必须优先覆盖**优先攻击目标**。

### 6.5 己方援助

- 两名玩家同时与同一个怪物战斗时，**怪物会同时与两名玩家建立双向战斗关系**。
- 当前设计不强制组队，但允许"自然协作"——谁先打到算谁的，怪物按 AI 逻辑选择目标攻击。
- 挑衅期缩短为 2 秒后，路人玩家帮忙输出的体验得到改善。

### 6.6 仇恨数据维护

- **累计伤害按关系对维护**：怪物 M 对玩家 A 的伤害累计，只存在于 M→A 的关系存续期间。
- 某条关系断开（脱战）时，该关系对的累计伤害**立即清零**。
- 不区分伤害来源（普攻、技能、DOT 均计入）。

## 7. 脱战机制（Disengage）

**双向脱战原则**：每个实体独立维护自己的敌人列表。当某条关系满足脱战条件时，**双方同时**从各自的敌人列表中移除对方。

- **整体战斗状态**：敌人列表非空 → 处于战斗中；敌人列表为空 → 整体脱战。
- 死亡立即清除自己的所有敌人列表，同时从所有其他实体的敌人列表中移除自己。

满足以下**任一条件**即可判定某条关系脱战：

> **领地内免疫脱战**：若玩家当前位于该怪物**领地范围内**，则该关系**不会因任何脱战条件而断开**。玩家必须离开怪物领地后，才能正常脱战。

### 条件 1：安全脱离
- 玩家**已离开**该怪物的领地范围。
- 双方距离 **> A**（较近阈值）。
- 并且，在最近 **T1 秒**内，双方**没有互相造成过伤害**。
- 并且，维持上述状态持续 **S1 秒**。

### 条件 2：彻底逃离
- 玩家**已离开**该怪物的领地范围。
- 双方距离 **> B**（较远阈值，**B > A**）。
- 维持该状态持续 **S2 秒**（通常 **S2 ≤ S1**）。

### 7.1 脱战后行为

- **怪物**：进入**缓慢回血**状态，直到回满或再次被拉入战斗。脱战后 `InCombat` 标志重置为 false，恢复 AI 巡逻和碰撞检测。
- **玩家**：可以正常移动、嗑药、休整；若再次碰撞则重新进入战斗。

## 8. 胜利与失败

- **怪物胜利条件**：玩家血量归 0 或玩家成功脱战。
- **玩家胜利条件**：怪物血量归 0。
- **玩家死亡惩罚**：
  - 在当前地图的**玩家出生点复活**。
- **怪物死亡奖励**：
  - 经验、掉落物分配机制待技术设计时确定（可考虑按伤害贡献分配）。

## 9. 视觉与体验建议

1. **战斗光环**：进入战斗后，角色脚下出现轻微光效，方便玩家快速识别自己是否还在战斗中。
2. **SkillBar**：屏幕右下角显示已装备技能的 CD 状态。
3. **先手突进**：角色移向敌人 30% 后弹回原位再开战，增强"撞上去"的打击感。详见 [`movement-system.md`](../movement/movement-system.md) §7.2。
4. **角色动作栏**：每个角色（玩家+怪物）正下方磁吸一个动作栏，宽与角色正方形相同，高度为两排文字。第一排显示当前蓄力技能名，第二排显示蓄力进度条（金色填充）。当前为测试阶段一直显示，后续可改为仅战斗中显示。

## 10. 怪物领地与追击边界（新增）

### 10.1 领地范围

- 每个怪物配置一个**领地范围**（圆形或矩形，由策划在配置表中设定）。
- 领地中心通常为怪物的**出生点**。

### 10.2 追击规则

| 场景 | 行为 |
|------|------|
| 目标在领地内 | 怪物**无限追击**，**完全免疫脱战**（领地内不会因任何脱战条件断开关系）。 |
| 目标离开领地 | 怪物继续追击，开始计算**追击超时**（超时时间由怪物配置表字段 `ChaseTimeout` 控制）。 |
| 追击超时 | 怪物放弃追击，进入**回归状态**。 |

### 10.3 回归状态（特殊例外）

> **回归状态是战斗系统中唯一的特殊例外状态**：其规则与正常战斗关系冲突，目的是强制怪物尽快回到领地，避免无限在领地外停留。

- 进入回归状态时，怪物**立即解除与所有外部实体的双向战斗关系**。
- 怪物向领地内的**巡逻点**移动（回归过程中不主动追击任何人）。
- 回归过程中套用一个**回归 Buff**：**50% 减伤 + 持续回血 + 移动速度提升**。该 Buff 在怪物回到领地巡逻点后**立即移除**。
- **回归过程中被攻击**：玩家仍可对回归中的怪物造成伤害，但**不建立战斗关系**、**怪物不反击**、**双方不进入战斗状态**。
- **回到巡逻点后**：清除回归 Buff，恢复**领地内巡逻 AI**（在巡逻点之间随机移动）。
- **回归过程中若碰撞到新实体**：按正常碰撞规则处理（建立双向战斗关系、可能触发先手等），此时怪物退出回归状态，转入正常战斗 AI。

### 10.4 巡逻点

- 每个怪物在 Luban 配置表中手动配置**多个巡逻点**（坐标列表）。
- 领地内巡逻时，怪物在巡逻点之间**随机选择下一个目标点**移动。
- 移动速度为正常巡逻速度（可与追击速度不同，由策划配置）。

## 11. PVP 兼容性预留（新增）

- **当前版本**：玩家之间碰撞仅阻止移动，不触发战斗、不建立战斗关系、不适用仇恨机制。
- **预留设计**：双向网状战斗关系模型天然支持 PVP 扩展。未来开放 PVP 时，仅需：
  1. 在碰撞检测中增加"玩家 vs 玩家"的战斗关系建立逻辑；
  2. 为玩家增加"可攻击玩家"的阵营/模式判断；
  3. 先手攻击逻辑（FirstStrikeHaste）对玩家同样生效。
- 当前代码实现时，关系系统应使用**通用接口**（不硬编码"玩家只能打怪物"），避免未来重构。
