# 掉落/拾取系统设计

> 版本：V0.1
> 日期：2026-05-04
> 状态：已实现

---

## 1. 概述

怪物死亡时在地图上生成掉落物实体，玩家通过碰撞拾取。这是游戏循环闭环的关键：打怪 → 掉落 → 拾取 → 变强。

### 1.1 现状

- 怪物死亡：经验直接加给击杀者（LevelUpService.OnMonsterDeath）
- 掉落物：怪物表有 `drop_items` 字段（格式 `itemId:count`），但**没有任何代码使用它**
- 宝箱系统：已有 ChestManager + Chest 实体 + 碰撞交互 + 协议，可作为参考
- 物品系统：已有 3 个物品（仙贝/精魔石/金币袋），背包管理完整

### 1.2 设计目标

1. 怪物死亡时根据掉落表生成地图上的掉落物实体
2. 玩家碰撞掉落物自动拾取，物品进背包
3. 掉落物有存在时间，超时消失
4. 经验分配：击杀者独占（当前逻辑不变，后续可扩展）

## 2. 配置表

### 2.1 掉落表（TbDropGroup）

新增 Luban 表，定义掉落规则：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | int | 掉落组 ID |
| name | string | 掉落组名称 |
| entries | list\<DropEntry\> | 掉落条目列表 |

### 2.2 掉落条目（DropEntry bean）

| 字段 | 类型 | 说明 |
|------|------|------|
| item_id | int | 物品 ID |
| count_min | int | 最小数量 |
| count_max | int | 最大数量 |
| weight | int | 权重（越大越容易掉） |
| guaranteed | bool | 是否必掉 |

### 2.3 怪物表关联

`common_tbmonster` 的 `drop_items` 字段改为 `drop_group_id`（int），引用 TbDropGroup。

**过渡方案**：保留 `drop_items` 兼容旧格式，新增 `drop_group_id` 字段。代码优先用 `drop_group_id`，为 0 时 fallback 到 `drop_items` 简单解析。

### 2.4 掉落物实体配置

不需要单独配置表，硬编码常量即可：

| 参数 | 值 | 说明 |
|------|-----|------|
| 掉落物存在时间 | 120 秒 | 超时自动消失 |
| 掉落物拾取范围 | 1 格 | 碰撞即拾取 |
| 同格最大掉落物 | 10 个 | 防止堆积 |
| 掉落偏移 | 死亡位置 ±1 格 | 随机散落 |

## 3. 服务端设计

### 3.1 掉落物运行时（DropItemEntity）

```csharp
public class DropItemEntity
{
    public long DropId;          // 唯一 ID（自增）
    public int ItemId;           // 物品 ID
    public int Count;            // 数量
    public string MapName;       // 所在地图
    public int X, Y;             // 格子坐标
    public long SpawnTime;       // 生成时间（Unix 秒）
    public long OwnerId;         // 归属玩家（0=所有人可拾取）
    public float OwnerLockTime;  // 归属锁定时间（秒），过后所有人可拾取
}
```

### 3.2 DropManager

```csharp
public class DropManager
{
    // 掉落物存储：<mapName, List<DropItemEntity>>
    private Dictionary<string, List<DropItemEntity>> _drops = new();
    private long _nextDropId = 1;

    // 怪物死亡时调用
    public List<DropItemEntity> GenerateDrops(int monsterId, string mapName, int x, int y, long killerId);

    // 玩家碰撞拾取
    public (bool ok, int itemId, int count) TryPickup(long playerId, string mapName, long dropId);

    // Tick：清理超时掉落物
    public List<long> TickExpired(double dt);

    // 获取地图上所有掉落物（给新进地图的玩家同步）
    public List<DropItemEntity> GetDrops(string mapName);

    // 移除指定掉落物
    public void RemoveDrop(string mapName, long dropId);
}
```

### 3.3 掉落生成流程

```
MonsterManager.OnMonsterDeath(instanceId, attackerId, monsterId)
  → DropManager.GenerateDrops(monsterId, map, x, y, attackerId)
    1. 查 TbDropGroup（或 fallback 解析 drop_items）
    2. 按权重随机选择掉落条目
    3. 生成 DropItemEntity，设置 OwnerId=attackerId，OwnerLockTime=30s
    4. 广播 DropSpawnNotify 给地图上所有玩家
  → LevelUpService.OnMonsterDeath（经验，不变）
```

### 3.4 拾取流程

```
玩家移动到新格子 → MapService 检查该格是否有掉落物
  → DropManager.TryPickup(playerId, map, dropId)
    1. 检查归属（OwnerId=0 或 OwnerId=playerId 或 已过锁定时间）
    2. 添加物品到背包
    3. 移除掉落物
    4. 广播 DropPickupNotify
```

**简化方案**：不做碰撞拾取，改为**自动拾取**——玩家走到掉落物所在格子时自动触发。这样不需要客户端发请求，服务端在 MoveComplete 时检查即可。

### 3.5 超时清理

GameService.Tick 中调用 DropManager.TickExpired(dt)：
- 掉落物存在超过 120 秒 → 移除，广播 DropRemoveNotify
- 归属锁定超过 30 秒 → OwnerId 置 0，所有人可拾取

## 4. 协议设计

### 4.1 新增消息

```protobuf
// 掉落物信息
message DropItemInfo {
  uint64 drop_id = 1;       // 掉落物唯一 ID
  uint32 item_id = 2;       // 物品 ID
  uint32 count = 3;         // 数量
  int32 x = 4;              // 格子 X
  int32 y = 5;              // 格子 Y
  uint64 owner_id = 6;      // 归属玩家（0=所有人可见可拾取）
}

// 掉落物生成通知（广播给地图上所有玩家）
message DropSpawnNotify {
  repeated DropItemInfo drops = 1;
}

// 掉落物拾取通知（广播给地图上所有玩家）
message DropPickupNotify {
  uint64 drop_id = 1;       // 被拾取的掉落物 ID
  uint64 picker_id = 2;     // 拾取者 ID
  uint32 item_id = 3;       // 物品 ID
  uint32 count = 4;         // 数量
}

// 掉落物消失通知（超时/被拾取）
message DropRemoveNotify {
  repeated uint64 drop_ids = 1;
}
```

### 4.2 message_id 新增

```
GAME_DROP_SPAWN_NOTIFY = 420
GAME_DROP_PICKUP_NOTIFY = 421
GAME_DROP_REMOVE_NOTIFY = 422
```

### 4.3 现有协议变更

`MapInfoSyncNotify` 新增 `repeated DropItemInfo drops = 5;`，玩家进地图时同步当前掉落物。

## 5. 客户端设计

### 5.1 掉落物渲染（DropItem）

参考 Chest 的实现方式，用 `_Draw()` 直接绘制，不需要美术素材：

```
掉落物外观：
- 底部：白色半透明圆形光晕（表示可拾取范围）
- 中间：彩色方块（颜色按品质：白/绿/蓝/紫/橙）
- 顶部：物品数量文本（>1 时显示）
- 动画：轻微上下浮动（sin 波）
```

### 5.2 DropManager（客户端）

```csharp
public partial class DropManager : Node
{
    // 存储当前地图的掉落物节点
    private Dictionary<long, DropItem> _drops = new();

    // 收到 DropSpawnNotify → 创建 DropItem 节点
    // 收到 DropPickupNotify → 播放拾取特效 + 移除节点 + 浮动文字
    // 收到 DropRemoveNotify → 移除节点
    // 收到 MapInfoSyncNotify → 批量创建掉落物
}
```

### 5.3 拾取反馈

- 拾取时播放浮动文字：`"+2 金苹果"`（复用 ChestManager 的 ShowItemFloatingTexts）
