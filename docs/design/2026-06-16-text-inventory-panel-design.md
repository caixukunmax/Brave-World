# 文字背包面板 redesign

## 背景与目标

现有背包是 `GridContainer` 5 列的图标格子（`76×76` 按钮 + 图标 + 名字 + 数量）。本设计将其改为**纯文字流式面板**：

- 不再有图标，完全以“道具名×数量”形式呈现。
- 背包被视为一个固定字符容量的容器。
- 玩家可以拖动道具重新排序，其他道具自动避让。

目标：打造一种独特、紧凑、可自由整理的“文字背包”体验，同时与现有服务器道具数据（`Game.ItemInfo`、`max_pile_num`、品质等）兼容。

---

## 核心设计决策

| 决策项 | 选择 |
| --- | --- |
| 布局方式 | 纯文字流式布局，自动换行 |
| 宽度 | 可配置，默认 30x（x = 一个汉字宽度） |
| 高度 | 可配置，默认 10 行 |
| 字符宽度 | 汉字 = 1x，乘号“×” = 1x，数字 = 0.6x |
| 重排方式 | 流式重排：拖动改变道具顺序，其他道具自动补位 |
| 堆叠规则 | 同名道具自动合并，超过 `max_pile_num` 才分条 |
| 交互 | 左键拖动排序，右键弹出使用/丢弃菜单 |
| 溢出处理 | 容量严格；拾取时若部分放不下，剩余道具留在原地 |

---

## 1. 布局与尺寸

### 1.1 面板尺寸

- 背包是一个**可配置宽高**的矩形字符区域。
- 宽度以“x”为单位，高度以“行”为单位。
- 默认值：宽 `30x`，高 `10` 行。
- 实际像素尺寸由渲染时字体大小决定，例如 `x = 16px` 时面板宽 `480px`。

### 1.2 调整尺寸的限制

- 允许运行时或配置中修改宽高。
- **缩小时必须保证已有道具仍能放得下**。若新尺寸会导致已有布局溢出，则：
  - 拒绝此次缩小（推荐），或
  - 临时扩展到能容纳的最小尺寸并提示玩家。

---

## 2. 容量计算

### 2.1 单个道具占用长度

```
占用格数 = 名字字数 + 1（乘号“×”）+ 数字位数 × 0.6
```

向上取整到最小可放置单位（实际实现中按浮点宽度计算，换行时按剩余空间判断）。

示例：

| 显示文本 | 计算 | 占用宽度 |
| --- | --- | --- |
| 魔法剑×1 | 3 + 1 + 1×0.6 | 4.6x |
| 高精宝石×30 | 4 + 1 + 2×0.6 | 6.2x |
| 金币×9999 | 2 + 1 + 4×0.6 | 6.4x |

### 2.2 总容量

```
总容量 = 宽度 × 高度（单位：x·行）
```

默认 `30 × 10 = 300` 格。

### 2.3 已用容量

所有道具条目占用宽度之和（按实际换行后的总面积计算，注意行尾碎片空间可能浪费）。

UI 顶部显示：

```
背包    142 / 300
```

---

## 3. 道具显示规则

### 3.1 文本格式

- 始终显示完整数量，包括 `×1`。
- 使用全角乘号 `×`（U+00D7），与汉字等宽。
- 数字使用常规比例字体，按 `0.6x` 计算宽度。

### 3.2 品质颜色

道具文字按品质染色：

| 品质 | 颜色 |
| --- | --- |
| 0 普通 | 白色 `#FFFFFF` |
| 1 优秀 | 绿色 `#1AFF1A` |
| 2 稀有 | 蓝色 `#1A80FF` |
| 3 史诗 | 紫色 `#9933FF` |
| 4 传说 | 金色 `#FF8000` |

### 3.3 堆叠与分条

- 同名道具自动合并为一条。
- 当数量超过 `max_pile_num` 时，拆分为多条：
  - 例：`max_pile_num = 99`，持有 150 个生命药水 → `生命药水×99` + `生命药水×51`。

### 3.4 单条宽度上限

- **不允许截断发生**。单个道具条目的显示宽度必须小于等于面板宽度。
- 若某个道具（名字 + × + 数量）的宽度超过面板宽度，则视为该道具在当前背包尺寸下无法容纳：
  - 拾取时：直接拒绝放入，剩余道具留在原地。
  - 调整背包尺寸变小时：若导致已有条目超宽，则拒绝此次缩小。
- 因此策划需保证：常用数量下的道具名长度不超过面板宽度。例如默认 30x 宽度下，建议道具名不超过 6 个汉字，数量不超过 9999。

## 4. 交互

### 4.1 左键拖动排序

- 按住左键拖动某个道具条目。
- 被拖动的条目会跟随鼠标移动，并处于半透明状态。
- 当鼠标靠近某个可插入位置时，被拖条目会吸附到该位置；其他条目自动避让，使用 Tween 动画平滑移动到预览位置。
- 动画时长可配置，默认 `0.15s`，可在 DebugPanel-系统-背包 中调节。
- 松开左键后：
  - 若插入位置发生变化，向服务器发送排序请求，保存新顺序。
  - 若取消拖动（未变化或移出背包区域），所有条目动画回到原位置。

#### 4.1.1 排序持久化

- 客户端在拖拽落盘时发送 `InventoryReorderRequest`，携带新的道具顺序列表（`repeated int32 ordered_item_ids`）。
- 服务器在 `Role` 文档中新增 `inventory_order: List<int>` 字段保存该顺序。
- 服务器返回完整背包时，按照 `inventory_order` 对 `InventoryItem` 进行排序；未出现在 order 中的 `item_id` 按原有顺序追加到末尾。
- 拾取新道具时，新的 `item_id` 自动追加到 `inventory_order` 末尾。
- 道具被完全消耗/丢弃时，从 `inventory_order` 中移除对应 `item_id`。
- 服务端校验失败（如 order 中包含不存在的 `item_id`）时返回错误，客户端回滚到拖拽前的本地顺序。

### 4.2 右键菜单

- 右键点击道具条目弹出菜单：
  - 使用
  - 丢弃 x1
  - 丢弃全部

### 4.3 空背包与满背包

- 空背包：面板中央显示 `（空）`。
- 快满时：容量数字变橙色。
- 已满：容量数字变红色，面板边框高亮红色。

## 5. 边界情况

### 5.1 拾取导致条目变长而爆仓

场景：背包剩余 2x 空间，当前持有 `魔法剑×1`，拾取 9 个魔法剑。

处理：

- `魔法剑×1` → `魔法剑×9` 占用从 4.6x 变为 5.2x，仍在剩余空间内。
- `魔法剑×10` 占用 5.4x，会超出。
- 因此只拾取 8 个，`魔法剑×9`，剩余 1 个魔法剑**留在原地**（不进入背包）。
- 提示玩家：`背包空间不足，剩余 1 个魔法剑无法拾取。`

### 5.2 调整尺寸导致溢出

- 缩小宽度/高度前，先计算当前物品在新尺寸下是否放得下。
- 若放不下，拒绝调整并提示：`当前物品较多，无法缩小到该尺寸。`

### 5.3 服务器下发新物品与本地排序冲突

- 服务器始终是权威，客户端收到 `InventoryChanged` 后按服务器下发的顺序重新布局。
- 玩家自定义排序通过 `InventoryReorderRequest` 持久化到 `Role.inventory_order`，服务器在返回背包数据时按该顺序排列。

## 6. 实现要点

### 6.1 客户端文件

主要修改：

- `clinetcsharp/Scripts/InventoryUI.cs`：面板生命周期。
- `clinetcsharp/Scripts/InventoryUI.Build.cs`：改为文字流式容器。
- `clinetcsharp/Scripts/InventoryUI.Actions.cs`：右键菜单、拖拽事件。
- 新增 `clinetcsharp/Scripts/TextInventoryLayout.cs`：负责字符宽度计算、换行、容量检查。

### 6.2 关键算法

1. **MeasureItem(slot)**：根据名字和数量计算宽度。
2. **Reflow(items, width)**：按顺序将条目填入固定宽度行，返回每行内容。
3. **CanFit(items, width, height)**：判断当前物品是否能在给定尺寸放下。
4. **PickUp(itemId, count)**：计算能放入的数量，返回实际放入数和剩余数。

### 6.3 服务器配合

- 拾取逻辑按“文字长度容量”校验，不再按“格子数”校验。
- 服务器数据库仍按 `(role_id, item_id, count)` 聚合；返回客户端前按 `max_pile_num` 拆分为多条 `ItemInfo`。
- 服务器额外维护 `inventory_order` 数组，返回背包时按该顺序对 `InventoryItem` 排序；新道具默认追加到末尾。
- 服务器只校验总容量（按统一规则计算）。
- 容量常量当前硬编码在 `GameServer.Services.Core.GameConstants`：
  - `InventoryLineWidth = 30`
  - `InventoryLineCount = 10`
  - `InventoryTotalCapacity = 300`
  - `InventorySpacingWidth = 0.5f`
