## #007 掉落拾取系统联调完成

### 问题
怪物死亡时服务端不生成掉落物，客户端 DropManager 是死代码。

### 根因
- `DropManager.cs` 已完整实现，但 `GameLogicFactory` 未创建实例
- `MonsterManager.OnDamage` 死亡回调链中未调用 `GenerateDrops()`
- `EnterGameHandler`/`ChangeMapHandler` 的 `MapInfoSyncNotify` 未填充 drops
- `MoveCompleteHandler` 未检查脚下掉落物自动拾取

### 修改
1. **PlayerSessionManager.cs** — 新增 `object? DropManager` 挂载点（支持热更 DLL 跨程序集引用，不改接口）
2. **MonsterManager.cs** — 新增 `GetMonster()` + `DropManager` 属性；`Tick` 末尾调用 `DropManager.Tick(dt)`
3. **GameLogicFactory.cs** — `BindLevelUpService` 中创建 `DropManager`，绑定网络广播回调（`DropSpawnNotify`/`DropPickupNotify`/`DropRemoveNotify`），怪物死亡链式调用（先 `LevelUp` 再 `GenerateDrops`）
4. **EnterGameHandler/ChangeMapHandler** — `MapInfoSyncNotify` 加入 `drops` 列表
5. **MoveCompleteHandler** — 移动完成后调用 `TryAutoPickup()`
6. **重新生成 Protobuf 协议** — `build_proto.ts` 生成 C#/TS/Lua，修复 `LevelUpNotify.Agility` 字段缺失

### 验证
- 服务端 `dotnet build` 编译通过，0 警告 0 错误
- 客户端无需修改（已有 `DropManager` + `MapManager` 集成）

### 待确认
- Phase 3 端到端验证：需陛下实际运行游戏，杀怪后确认掉落物出现 + 自动拾取 + 背包更新
