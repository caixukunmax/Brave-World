# 2026-05-08 日报

## Godot 插件调试与修复

### 现象
陛下要求测试 Godot 插件，发现 `godot_execute` 等工具虽然在 gateway 加载了，但不出现在 agent session 的工具列表中。

### 根因分析（三层）

**第一层：manifest 缺少 contracts.tools 声明**
- ClawHub 的 `godot` 插件（1.2.7）的 `openclaw.plugin.json` 没有 `contracts.tools` 字段
- 根据 OpenClaw 文档，工具必须在 manifest 里声明才能被发现
- **修复**：在 manifest 中添加了 `"contracts": { "tools": ["godot_execute", "godot_sessions"] }`

**第二层：tools.alsoAllow 配置缺少 godot 工具**
- `tools.profile = "coding"` 只包含编码相关核心工具
- `tools.alsoAllow` 里有飞书工具，但没有 `godot_execute` 等
- **修复**：在 `openclaw.json` 的 `tools.alsoAllow` 中添加了 7 个 godot 工具

**第三层：两个 godot 插件路由冲突 + session 隔离**
- `godot-bridge`（自写）：精确路径匹配 `/godot/register`、`/godot/heartbeat` 等，`auth: "plugin"`
- `godot`（ClawHub）：前缀匹配 `/godot`，`auth: "gateway"`
- GDScript 插件调用 `/godot/register` → 走 `godot-bridge` 的路由（精确匹配优先）
- 但 `godot_execute` 工具读的是 `godot` 插件的内存 session Map
- 两个插件各自维护独立的内存 session 存储，互不相通
- **结果**：GDScript 连到了 `godot-bridge`，但 `godot_execute` 找不到 session

### 最终修复方案
1. **禁用 ClawHub 的 `godot` 插件**（避免路由冲突）
2. **在 `godot-bridge` 中新增 `godot_execute` 和 `godot_sessions` 工具**
   - `godot_execute`：统一入口，支持所有 Godot 命令（scene.getCurrent, node.find, debug.tree, editor.play 等）
   - `godot_sessions`：列出所有已连接的 Godot 编辑器 session
3. **在 `godot-bridge.js` 中新增 `listSessions()` 方法**
4. **更新 `godot-bridge` 的 manifest**，添加 `godot_execute` 和 `godot_sessions` 到 `contracts.tools`

### 验证结果
| 工具 | 状态 | 结果 |
|------|------|------|
| `godot_sessions` | ✅ | 检测到 1 个连接（clinetcsharp, Godot 4.6.2） |
| `godot_execute` → `editor.getState` | ✅ | playing: false |
| `godot_execute` → `scene.getCurrent` | ✅ | LoginScene |
| `godot_execute` → `debug.tree` | ✅ | 返回完整场景树 |
| `godot_debug_screenshot` | ✅ | 1920×1009 截图成功 |

### 限制
- `debug.tree` 和 `node.find` 只能访问编辑器场景树，不能访问运行时场景树
- 截图捕获的是编辑器视口，不是游戏运行画面
- 这是 GDScript 插件使用 `EditorInterface.get_edited_scene_root()` 的固有限制

## #004 直接编辑数值 — 保存链路问题确认

### 现象
配置文件 `debug_panel_config.cfg` 中 `profile_1.healthbar.length_scale=0.919`，而用户输入的是 `0.91`。

### 根因定位
- `0.919` = `102.0f / 111.0f` 的 F3 格式化结果（即默认值）
- **不是"加载错了"，而是"用户修改后的值没有真正保存进 cfg"**
- 重启后回退到默认 profile 值

### 保存链路分析
```
输入框 ApplyValue() → slider.Value → OnComponentChanged()
→ profile.SetData(... SyncToData()) → ScheduleSave() → Owner.SaveConfigFromTab()
→ DebugPanel.SaveConfig() → EntityTab.SaveConfig() → SaveCurrentProfileData()
→ WriteProfileConfig() → WriteComponentData() → config.SetValue("length_scale", (double)bar.LengthScale)
```

### 待排查的 4 个关键点
1. 输入框 `ApplyValue()` 时实际拿到的文本值
2. `_lengthScaleSlider.Value` 在 `SyncToData()` 时是多少
3. `profile.GetData("healthbar").LengthScale` 在 `SaveCurrentProfileData()` 后是多少
4. `WriteProfileConfig()` 真正写出的 `length_scale` 是多少

### 可能的根因方向
- 输入框没把值写进 slider（ApplyValue 链路断裂）
- slider 写进 profile 失败（SyncToData 时机问题）
- profile 被后续默认值覆盖（RefreshComponents 时重置）
- save 定时器/刷新顺序把新值冲掉了（ScheduleSave 1秒延迟期间被 Refresh 覆盖）

## 经验教训
1. **OpenClaw 插件工具注册三要素**：manifest `contracts.tools` 声明 + `api.registerTool()` 调用 + `tools.alsoAllow` 配置，缺一不可
2. **多插件路由冲突**：精确匹配优先于前缀匹配，但两个插件维护独立的内存状态会导致数据隔离
3. **Godot 编辑器插件的固有限制**：`EditorInterface` API 只能访问编辑器场景树，不能访问运行时场景树
4. **浮点精度陷阱**：`102.0f / 111.0f = 0.918918...` → F3 格式化为 `0.919`，看起来像"值变了"其实是默认值的精确表示
