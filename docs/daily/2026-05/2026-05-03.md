# 2026-05-03 日报 — Brave-World 项目

## 调试面板 EntityTab 组件化重构（续）

### 问题 1：ActionBarComponent 重复 CollapsibleContainer
- **现象**：调试面板里"动作栏"组件出现了两次折叠标题
- **根因**：CC 修了 7 个组件的重复 CollapsibleContainer，但漏了 ActionBarComponent。BuildUI 里自己创建了内层 CollapsibleContainer，而 AddComponentUI 也创建了外层的
- **修复**：去掉 ActionBarComponent.BuildUI 里的 CollapsibleContainer，直接往 parent 里加控件；同时补上 SliderValueInput.Attach
- **经验**：批量修改后必须逐个验证，不能假设"都改了"

### 问题 2：删除按钮与组件名称同行
- **需求**：删除按钮和组件标题出现在同一行
- **修复**：CollapsibleContainer 新增 HeaderRow（HBoxContainer），标题按钮和删除按钮都在 HeaderRow 里；暴露 HeaderRow 属性供外部添加按钮

### 问题 3：移除组件后视觉残留（根治）
- **现象**：在调试面板移除 levelbadge 组件后，等级徽章仍然显示
- **根因**：ApplyProfile 只处理 Profile 有的组件，缺少的组件属性不会重置，残留旧状态
- **修复**：ApplyProfile 开头加 ResetEntityToDefaults，先把所有可选属性设为默认/隐藏，再按 Profile 覆盖
- **经验**：**先 Reset 再 Override** 是处理可选配置的通用模式，以后加新组件只需在 Reset 里加默认值

### 问题 4：ApplyProfile 不触发重绘（根治）
- **现象**：调试面板调整怪物"角色大小"后，怪物视觉没变化
- **根因**：ApplyProfile 直接赋值 `entity.VisualSizeScale = ...`，不触发 QueueRedraw。只有 Set* 方法才触发
- **修复**：ApplyProfile 里改用 SetVisualSizeScale、SetBorderWidthScale、SetHealthBarLengthScale 等方法
- **经验**：**属性赋值 vs Set* 方法**——Set* 方法有副作用（QueueRedraw），直接赋值没有。外部调用应优先用 Set* 方法

### 问题 5：进入游戏巨卡（严重 Bug）
- **现象**：进入游戏后 FPS 降到 7-10，持续卡顿
- **排查过程**：
  1. 先禁用 ResetEntityToDefaults → 不卡 → 排除
  2. 恢复 ResetEntityToDefaults，禁用 SetupLabels 后的 ApplyProfile → 不卡 → 确认是 ApplyProfile 导致
  3. 加 ApplyProfile 调用计数 → 发现被调了 16+ 次！
  4. 加 SetupLabels 日志 → 发现 SetupLabels 也被调了 16+ 次
  5. **找到循环**：ApplyProfile → SetVisualSizeScale → SetupLabels → 完成后调 ApplyProfile → 无限循环
- **根因**：Player 重写了 SetVisualSizeScale/SetBorderWidthScale，在里面调了 SetupLabels()。而 ApplyProfile 调了 SetVisualSizeScale，触发了整个循环
- **修复**：
  1. SetVisualSizeScale/SetBorderWidthScale 去掉 SetupLabels，只保留 QueueRedraw（改大小不需要重建标签）
  2. SetGridSize 改成 UpdateAllLabelPositions（改格子大小只需更新位置）
  3. SetTextAlignment 改成 UpdateAllLabelPositions
  4. SetupLabels 完成后调 ApplyProfile（循环根因已消除，现在安全）
- **经验**：**SetupLabels 是重量级操作（创建节点），不应该被 Set* 方法触发**。Set* 方法应该只做轻量更新（QueueRedraw/UpdatePositions）。循环 Bug 的排查方法：加调用计数 + 日志，看谁被反复调用

### 问题 6：Monster/NPC 不加入 group
- **现象**：ApplyProfileToAll 对 Monster/NPC 永远 applied=0
- **根因**：Monster/NPC 从没调用 AddToGroup，GetNodesInGroup 找不到
- **修复**：Monster.Setup 里加 AddToGroup("monster")，Npc.Setup 里加 AddToGroup("npc")

### 问题 7：启动时 Profile 不自动应用
- **现象**：进入游戏后玩家配置没生效，要点调试面板才应用
- **根因**：
  1. AssignDefaultProfileIds 在 CallDeferred 里执行，Player 还没 Ready（assigned=0）
  2. Monster/NPC 在 Manager 创建时没调 ApplyProfile
  3. EntityTab LoadConfig 里的 0.1s timer ApplyProfileToAll 被去掉了
- **修复**：
  1. MonsterManager/NpcManager 创建实体后直接调 ApplyProfile
  2. Player.SetupLabels 完成后调 ApplyProfile（循环已修，安全）
  3. AssignDefaultProfileIds 改为对已有 ProfileId 的实体也 Apply

### 问题 8：ApplyCurrentProfileDeferred 方法找不到
- **现象**：日志报 `Error calling deferred method: Method not found`
- **根因**：`Owner.CallDeferred("ApplyCurrentProfileDeferred")` 调的是 DebugPanel 上的方法，但方法是 EntityTab 的
- **修复**：改用 SceneTree.CreateTimer 延迟调用

### 问题 9：调试面板标题栏拖拽不工作
- **现象**：点击标题栏拖不动面板
- **根因**：DebugPanel._Input override 没调 base._Input()，DraggablePanel 的拖拽逻辑永远不会执行
- **修复**：加 `base._Input(@event)`
- **经验**：**C# override 必须显式调 base**，不像 Java 会自动调 super。这是容易遗漏的 Bug

---

## 铁律总结
1. **先 Reset 再 Override** — 处理可选配置的通用模式
2. **Set* 方法只做轻量更新** — 不触发 SetupLabels 等重量级操作
3. **C# override 必须显式调 base** — 不像 Java 自动调 super
4. **批量修改后逐个验证** — 不能假设"都改了"
5. **循环 Bug 排查** — 加调用计数 + 日志，看谁被反复调用

### 问题 10：折叠组件时整体下移一行
- **现象**：点击外观组件的折叠按钮，面板整体往下移动了一行
- **根因**：AddComponentUI 里多包了一层 wrapper VBoxContainer，折叠时 Content 隐藏但 wrapper 高度不收缩
- **修复**：去掉 wrapper，CollapsibleContainer 直接加到 _componentContainer
- **经验**：不需要多余的容器包装，CollapsibleContainer 本身就是 VBoxContainer
