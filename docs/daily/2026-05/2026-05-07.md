## #004 直接编辑数值 — 保存/加载链路排查（进行中）

### 问题: 修改值后重启游戏，值似乎没有保存
- **现象**: 陛下修改长度比例（如 0.919 → 0.910），保存后重启游戏，DebugPanel 里显示的值又变回 0.919
- **排查过程**:

#### 第一轮: 确认保存链路
- 在 `SliderValueInput.ApplyValue`、`BarGroupComponent.OnDbl`、`EntityTab.OnComponentChanged`、`DebugPanel.SaveConfig` 加日志
- **结果**: 拖动滑条 → `OnDbl` → `OnComponentChanged` → `SaveConfig` → 配置文件写入，整条链路正常
- 点击数值输入 → `ApplyValue` → `slider.Value = val` → `OnDbl` → 同样正常
- 配置文件 `debug_panel_config.cfg` 里确认写入了 `length_scale=0.91`

#### 第二轮: 确认加载链路
- 在 `EntityProfileManager.ReadComponentData`、`BarGroupComponent.SyncFromData` 加日志
- **结果**: `ReadComponentData` 从配置文件读到 `length_scale=0.91` ✅
- `SyncFromData` 收到 `LengthScale=0.91` ✅
- 配置文件确实是 `0.91`，不是 `0.919`

#### 第三轮: 发现 `AssignDefaultProfileIds` 时 Player 为 null
- **根因**: `EntityProfileManager._Ready` → `CallDeferred(AssignDefaultProfileIds)` 执行时 Player 还没加入场景树
- 日志: `AssignDefaultProfileIds: player=null, assigned 0 entities`
- **修复**: 在 `DebugPanel.DeferredLoadConfig` 里（此时 Player 已存在）调用 `EntityProfileManager.ApplyAllProfiles()`
- 新增 `EntityProfileManager.ApplyAllProfiles()` 方法，遍历所有 Profile 逐一 `ApplyProfileToAll`

#### 第四轮: 确认 ApplyProfile 执行正确
- 在 `SetHealthBarLengthScale` 加调用栈日志
- **结果**: `SetHealthBarLengthScale: 0.9189189 → 0.91` ✅
- `ApplyProfile` 被多次调用（`ApplyAllProfiles` + `DeferredLoadConfig` 里的 `ApplyRoleInfo` 后），但都是 0.91 → 0.91
- 没有任何代码把值覆盖回 0.919

#### 第五轮: 确认 UI 显示
- `SyncFromData: LengthScale=0.91, FormatStr=0.910` ✅
- `SyncToCurrentValues: hpBar.LengthScale=0.91` ✅
- **日志显示一切数据正确，但陛下仍报告看到 0.919**

### 经验教训
1. **Godot 场景树时序**: Autoload 的 `_Ready` + `CallDeferred` 不保证其他节点已就绪，需要在使用时再次检查
2. **默认值陷阱**: `EntityBase.HealthBarLengthScale` 默认值是 `102/111 ≈ 0.919`，如果 `ApplyProfile` 没执行，实体就用默认值
3. **日志驱动的排查**: 5 轮日志逐步缩小范围，最终确认数据链路正确，问题可能出在 UI 渲染或用户操作时机

## 今日铁律
- **场景树时序不确定**: `CallDeferred` 不保证其他节点已 Ready，关键操作需要延迟到确认节点存在后再执行
- **默认值是"幽灵"**: 属性默认值（如 0.919）可能在 Profile 应用前短暂可见，造成"值没保存"的假象
