## 实体系统架构设计讨论

### 议题：NPC 应该拥有 Monster 的一切能力，继承链怎么设计？

**讨论过程**：
1. 最初想法：NPC 继承 Monster → 但 Monster 不是 NPC 的"基础版"，它们是平级的
2. 第二方案：抽 CombatEntity 中间层 → Monster/Npc/Boss 都继承它 → 但 Boss/Pet/Guard 继承 Monster 不合理
3. 第三方案：**组件化 > 继承** → EntityBase + 能力组件，任意组合

**最终决策**：

**服务端：组件化驱动**
- EntityBase + 能力组件（Combat/Move/Cast/AI/Interact/Gather）
- 按实体类型配置组件组合
- Monster → {Combat, Move, AI, Cast}
- Npc → {Combat, Interact}
- GatherNode → {Combat, Gather}

**客户端：按渲染类型继承**
- EntityBase + 渲染组件（只管 UI/动画）
- Monster/Npc/Boss 按渲染方式分继承
- 前端组件只管"怎么画"，不做逻辑计算

**核心原则**：
- 服务端决定"是什么"（EntityType + 组件列表）
- 客户端决定"怎么画"（按类型创建渲染实体）
- 协议：EntityType + 组件列表，服务端告诉客户端实体信息
- 前端区分标准是"渲染方式不同"，不是"逻辑能力不同"

### 踩坑记录
- Luban 的 bean/enum/table 定义不能在 common.xml 和 __beans__/__enums__/__tables__.xlsx 之间重复
- Luban 从 xlsx 文件自动推断 table（sheet 名匹配 bean 名时），不需要在 __tables__.xlsx 显式注册
- __enums__.xlsx 中新增枚举值必须加在对应 enum 的末尾，不能加在别的 enum 后面
- build_tables 生成到 `servercsharp/data/tables`，运行时从 `bin/Debug/net8.0/data/tables` 读取，需要手动复制

## 今日铁律/经验
1. **Luban 定义源唯一原则**：同一个 bean/enum/table 只能出现在一个来源（xml 或 xlsx），否则报 duplicate
2. **Luban 自动推断 table**：xlsx 文件存在且 sheet 名匹配 bean 名时，Luban 自动注册 table，__tables__.xlsx 不需要也不应该重复注册
3. **__enums__.xlsx 枚举值归属**：新增枚举值必须紧跟在对应 enum 定义后面，不能加到其他 enum 的末尾
4. **DOT tick 日志去重**：通用方法加开关参数（如 broadcastDamageLog），避免调用方和被调用方各播一次
5. **护盾日志顺序**：先算盾吸收再播日志，日志反映实际伤害而非原始伤害
