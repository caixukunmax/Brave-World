# tslua2 日报 2026-05-06

## #004 直接编辑数值 — 两个 Bug 修复

### Bug 1: 输入值后没能正确保存
- **现象**: 通过 LineEdit 输入精确数值后，值似乎没有正确保存
- **根因**: `FocusExited` 和 `_Input` 的点击外部处理双重触发 `ApplyValue`
  - `_Input` 先执行 `ApplyValue` → `applying = false` → `edit = null`
  - `FocusExited` 再执行 `ApplyValue` → `applying` 已重置 → 再次执行 → NRE（edit 为 null 时访问 edit.Text）
  - Godot C# 吞了 NRE，面板继续运行但保存流程可能被中断
- **修复**: `FocusExited` 回调中先检查 `edit == null`，已被 Apply 过则跳过

### Bug 2: 点击其他位置没有取消输入状态
- **现象**: 进入输入状态后，点击面板内其他位置，LineEdit 不关闭
- **根因**: `SliderValueInput.HandleUnhandledInput` 在 `_UnhandledInput` 中调用
  - `_UnhandledInput` 只在输入未被处理时触发
  - 点击 DebugPanel 内的控件通常被 `_Input` 消耗，到不了 `_UnhandledInput`
  - 点击不可聚焦控件（Label 等）时 `FocusExited` 也不触发
  - 导致 LineEdit 既不失焦也不被 `_UnhandledInput` 关闭
- **修复**: 将点击外部检测从 `_UnhandledInput` 移到 `_Input`
  - 新增 `SliderValueInput.HandleInput` 方法
  - 用 `GetGlobalRect().HasPoint()` 判断点击是否在 LineEdit 内部
  - 点击 LineEdit 外部 → 关闭并应用值

### 修改文件
1. `SliderValueInput.cs` — 新增 `HandleInput`，`FocusExited` 加 null 保护
2. `DebugPanelTab.cs` — `AttachValueLineEdit` 的 `FocusExited` 加 null 保护
3. `DebugPanel.cs` — `_Input` 调用 `SliderValueInput.HandleInput`，`_UnhandledInput` 移除旧调用

### 经验教训
1. **`_Input` vs `_UnhandledInput`**: 需要可靠捕获所有点击事件时用 `_Input`，`_UnhandledInput` 只在输入未被消耗时触发
2. **`FocusExited` 双重触发**: 当同时用 `_Input` 处理点击外部和 `FocusExited` 处理失焦时，两者可能对同一事件都响应，需要用状态标志（如 `edit == null`）防止双重执行
3. **`applying` 标志不够**: `applying` 在 `ApplyValue` 末尾被重置，无法防止第二次调用；用 `edit == null` 检查更可靠
