# 实体视觉表现设计

> 状态：已实现
> 日期：2026-05

---

## 1. 血条长度比例基准统一


当前血条、MP 条、施法条的 `长度比例` 是按 `GridSize` 计算的：

`Length = GridSize × LengthScale`

这会带来一个语义偏差：

1. 实体本体视觉宽度已经允许通过 `VisualSizeScale` 调整
2. 但条形长度仍然以格子宽度为基准
3. 结果就是当用户把 `长度比例=1` 时，视觉上不一定等于“和当前实体一样宽”

对怪物和 NPC 来说，这个体验尤其怪，因为用户直觉上会把“长度比例=1”理解成“正好铺满这只实体”。

## 2. 目标

统一条形长度比例的语义：

1. `长度比例 = 1`
2. 代表条形长度 = 当前实体的总外轮廓宽度
3. 而不是固定等于地图格子宽度

## 3. 方案

将长度计算基准从 `GridSize` 改为 `VisualOuterSize`：

- 血条：`HealthBarLength = VisualOuterSize × HealthBarLengthScale`
- MP 条：`MpBarLength = VisualOuterSize × MpBarLengthScale`
- 施法条：`CastBarLength = VisualOuterSize × CastBarLengthScale`

这样：

1. 当实体本体缩小或放大时，条形控件会保持同一套相对语义
2. `长度比例=1` 会稳定表现为“和实体一样宽”
3. 怪物、NPC、玩家都走同一条规则

## 4. UI 同步

调试面板里的“长度”只读值也必须改成按同一基准显示，避免：

1. 真实绘制长度已经变了
2. 只读显示还在按 `GridSize × Scale`
3. 造成“数值和视觉不一致”

## 2. 方块像素对齐


当前玩家、野怪、NPC 的方块本体虽然共享同一套外观参数，但在某些截图里仍会出现：

- 同样参数下，某一张看起来更宽一点
- 尤其底部轮廓更容易出现“胖瘦不一致”的感觉

这说明问题已经不在标签布局，而在实体本体的像素轮廓稳定性。

## 2. 根因

当前方块绘制仍然存在两层不稳定因素：

1. `VisualOuterSize / BorderWidth` 允许带小数参与最终轮廓计算
2. 边框通过描边式圆角路径绘制，容易受半像素落点影响

结果就是：

- 同样配置
- 在不同截图或不同位置
- 边框可能会因为描边落点不同，看起来宽 1px 左右

## 3. 目标

1. 同样参数必须得到同样像素轮廓
2. 边框始终向内吃，不允许再把轮廓向外撑胖
3. 点击命中范围与可见外轮廓一致

## 4. 方案

### 4.1 整数像素语义

统一把实体本体核心尺寸收口为整数像素：

- `VisualOuterSize`
- `BorderWidth`
- `VisualSize`

其中：

- `VisualOuterSize`：总外轮廓尺寸
- `BorderWidth`：整数像素边框宽度
- `VisualSize`：内部填充尺寸，按 `VisualOuterSize - BorderWidth * 2`

### 4.2 边框改为内缩填充

不再使用“沿轮廓线描边”的方式作为最终边框。

改为：

1. 先画外层边框色圆角矩形
2. 再画向内收缩后的背景色圆角矩形

这样边框完全向内吃，外轮廓不会因为描边宽度而外扩。

### 4.3 中心填充不受边框底色污染

在“先画边框色外层、再画中心填充”的双层方案下，如果中心填充继续使用半透明颜色直接叠加，
就会出现一个副作用：

- 背景色会和下方边框色混色
- 例如：纯黑 + 低不透明度 + 红边框
- 最终中心看起来会变成酒红色，而不是用户想要的黑色

因此中心填充需要先解析成最终可见色，再以不透明方式填入。

当前项目在黑底地图上的等效规则是：

- `finalFillRgb = bgColor.rgb * bgOpacity`
- `finalFillAlpha = 1`

这样：

1. 纯黑永远保持纯黑
2. 红色低不透明度会表现成深红
3. 中心区域不会再被边框底色污染

### 4.3 命中范围同步

实体点击判定与 `HitTest` 应基于 `VisualOuterSize`，而不是内部填充尺寸。

否则会出现：

- 看得见的边框能点到
- 但代码命中范围却更小

## 5. 验收标准

1. 同样参数截图对比时，方块本体宽度不再一会儿胖一会儿瘦
2. 底部轮廓在不同截图里保持一致
3. `scale = 1.0` 时，含边框的总外轮廓仍然贴格子内边，不越界

## 3. 标签显示格式


当前玩家与野怪的第一行标签都带等级，但格式不一致：

- 玩家：`Lv.2 测试勇者`
- 野怪：`LV.2 野狼`

这会让同一套世界标签在视觉上不统一，也不利于后续继续收口标签规则。

## 2. 目标

统一所有核心战场单位第一行名字格式：

- 玩家：`LV.{level} {name}`
- 野怪：`LV.{level} {name}`

其中：

- `LV.` 使用全大写
- 等级与名字之间保留一个空格

## 3. 约束

### 3.1 玩家

玩家第一行标签和等级角标都使用同一套等级前缀：

- 第一行：`LV.{level} {name}`
- 等级角标模板：`LV.{level}`

### 3.2 野怪

野怪第一行继续绑定真实怪物等级与名称，格式固定为：

- `LV.{level} {name}`

## 4. 预期收益

- 玩家、野怪名字行风格统一
- 调试截图与战斗场景可读性更稳定
- 后续如果扩展 NPC 名字行，也有明确可复用格式

## 4. 标签布局一致性


当前玩家、野怪、NPC 虽然都显示为格子内的标准方块，但标签布局并没有完全使用同一套语义：

- 野怪 / NPC 使用 `EntityBase` 的四行标签基线布局
- 玩家仍保留旧的 `Player` 私有标签偏移链路
- 玩家自动字号曾使用独立公式，和野怪 / NPC 的默认字号推导不一致

这会导致一个直接问题：

- 调试面板里输入一样的标签参数
- 玩家和野怪看起来却不是同一种效果

用户感知上就会变成“方块好像错位了”“同样参数没有同样表现”。

## 2. 目标

统一玩家、野怪、NPC 的标签布局语义：

1. 四行标签都基于同一套基线公式计算
2. 自动字号也基于同一套默认公式计算
3. `X偏移 / Y偏移 / 居中` 的含义在三类实体上完全一致
4. 相同参数必须得到相同表现
5. 实体本体继续保持标准正方形渲染，不因标签链路不同而产生视觉错觉

## 3. 根因

根因不是格子不是正方形，也不是玩家和野怪本体用了不同的方块绘制逻辑。

本体渲染上，玩家、野怪、NPC 都共用：

- `EntityBase.VisualOuterSize`
- `EntityBase.VisualSize`
- `RenderComponents.AppearanceComponent`
- `EntityDrawUtils.DrawBody(...)`

真正分叉的是标签布局：

- 野怪 / NPC：`LabelYOffsets` 是“基于四行统一基线的相对偏移”
- 玩家：旧链路里的 `_labelOffsets` 曾按“绝对摆放位置”使用
- 玩家：`font size = 0` 时走的是私有自动字号公式

因此同样的 `Y偏移=0`：

- 野怪表示“落在这一行的标准基线上”
- 玩家却可能表示“落在节点局部坐标原点附近”

这就是“同参数不同表现”的根因。
即使偏移语义统一，如果自动字号公式不统一，文本密度和视觉重心仍然会不同。

## 4. 方案

### 4.1 统一四行标签基线算法

新增共享标签布局 helper，统一计算：

- 基础字号
- 行高
- 四行总高度
- 每一行的基线中心点

玩家、野怪、NPC 都使用这套 helper。

### 4.2 玩家旧偏移语义收口

玩家保留旧的数据结构以兼容调试拖拽与旧入口，但布局含义改为：

- `X偏移`：相对于统一基线的水平偏移
- `Y偏移`：相对于统一基线的垂直偏移
- `CenterX=true`：该行文本中心对齐到实体原点 X

也就是说，玩家不再把 `_labelOffsets` 当成绝对位置。

## 5. 非目标

本轮不改以下内容：

1. 不改玩家/怪物/NPC 的本体方块绘制公式
2. 不把等级角标并入四行标签
3. 不调整格子世界坐标换算公式

## 5.1 诊断辅助

为了区分“本体真的偏了”还是“标签/条形造成视觉错觉”，需要提供一套全实体共用的诊断 overlay：

1. 当前格子外框
2. 实体外轮廓框
3. 实体内部绘制框
4. 中心十字

该 overlay 必须对玩家、野怪、NPC 使用同一套绘制规则，不能再只给玩家单独画调试辅助线。

## 6. 验证标准

修复后应满足：

1. 玩家与野怪设置相同 `appearance + labels` 参数时，四行文本布局表现一致
2. `X偏移 / Y偏移 / 居中` 在玩家与野怪上的结果一致
3. NPC 因为已经走通用链路，表现继续保持与野怪一致

## 5. 玩家背景颜色可见性


当前玩家背景颜色调整链路本身是通的，但用户会感知为：

- 怪物 / NPC 改背景颜色很明显
- 玩家改背景颜色几乎没效果

这不是颜色没有写进去，而是玩家背景的历史默认可见度过低。

## 2. 根因

玩家默认外观配置长期使用：

- `BgOpacity = 0.1`

而怪物 / NPC 默认是：

- `BgOpacity = 0.9`

在近期“边框向内吃”的实体本体绘制规则下，玩家内部可见填充面积更小，
再叠加 `0.1` 的低不透明度，背景颜色变化就更容易被误判成“无效”。

## 3. 目标

1. 玩家背景颜色调整应当肉眼可见
2. 不改变“玩家整体比怪物更轻”的视觉方向
3. 对历史未自定义过的玩家默认配置做平滑兼容

## 4. 方案

### 4.1 提高玩家默认背景不透明度

将玩家默认 profile 的背景不透明度从 `0.1` 提高到 `0.35`。

这是一个折中值：

- 明显高于旧值，颜色变化可见
- 仍显著低于怪物 / NPC 的 `0.9`

### 4.2 兼容旧配置

对历史玩家 profile 做轻量归一化，仅处理“看起来仍是旧默认”的情况：

- `entity_type = player`
- `BgOpacity` 仍约等于 `0.1`
- `BgColor` 仍接近默认白色

满足以上条件时，自动提升到新的默认可见度。

如果用户已经显式改过背景色或不透明度，则不强行覆盖。

### 4.3 旧格式迁移默认值

在 legacy `player` section 缺少 `bg_opacity` 时，兼容默认值也同步改为新默认可见度。

## 5. 验收标准

1. 新玩家默认外观下，改背景颜色能明显看出差别
2. 老玩家若仍停留在旧默认外观，升级后背景颜色变得可见
3. 已显式自定义过背景色/不透明度的玩家配置不被粗暴覆盖
