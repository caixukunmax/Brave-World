# 实体系统架构

> 最后更新：2026-05-04

## 概述

Brave-World 实体系统采用 **服务端组件化 + 客户端渲染组件化** 的双层架构。

- **服务端**：EntityBase + 能力组件（Combat/Move/Cast/AI/Interact/Gather），按类型组合
- **客户端**：EntityBase + 渲染组件，按渲染方式分继承（Monster/Npc/Player...）
- **协议**：EntityType + 组件列表，服务端告诉客户端"这是什么"

**核心原则**：服务端决定"是什么"，客户端决定"怎么画"。

---

## 服务端架构

### ServerEntity（GameServer.Common.Entity）

所有实体的基类，包含：
- `EntityId` — 唯一 ID（Player=AccountId, Monster/Npc=InstanceId）
- `Type` — EntityType 枚举
- `MapName` / `X` / `Y` — 位置
- `Name` / `TemplateId` — 名称和模板 ID
- 组件字典 + 事件系统

### 组件列表

| 组件 | 用途 | 使用者 |
|---|---|---|
| CombatComponent | 属性字典 + HP/MP/战斗状态 | Player, Monster, Npc, Boss |
| MoveComponent | 移动速度/目标/时间 | Player, Monster, Boss |
| CastComponent | 技能列表/施法状态 | Player, Monster, Boss |
| AiComponent | AI 配置/状态/目标 | Monster, Boss |
| InteractComponent | NPC 交互 | Npc |
| GatherComponent | 采集配置 | GatherNode（预留） |
| PlayerComponent | 账号/角色/职业 | Player |

### 组件组合配置（EntityComponentConfig）

| EntityType | 组件列表 |
|---|---|
| Player | Combat, Move, Cast, Player |
| Monster | Combat, Move, AI, Cast |
| Npc | Combat, Interact |
| GatherNode | Combat, Gather |
| Boss | Combat, Move, AI, Cast |

### 地图状态类型（WorldDataTypes.cs）

- `MapPlayerState : ServerEntity` — 委托到 PlayerComponent/CombatComponent/MoveComponent/CastComponent
- `MapMonsterState : ServerEntity` — 委托到 CombatComponent/MoveComponent/AiComponent/CastComponent
- `MapNpcState : ServerEntity` — 委托到 CombatComponent/InteractComponent
- `MapState` — 单张地图的运行时状态（Players/Monsters/Npcs 字典）

### 事件系统

- `EntityEvent` — 事件基类，支持 `Handled` 短路
- `EntityEventType` — 事件类型枚举（Interact/CastStart/CastComplete/CastCancel/Gather/Damage/Death/Move）
- 组件通过 `InterestedEvents` 声明关心的事件，OnAttach 时自动订阅

### EntityId 同步规则

- Player: `AccountId` setter 自动设置 `EntityId = value`
- Monster: `InstanceId` setter 自动设置 `EntityId = value`
- Npc: `InstanceId` setter 自动设置 `EntityId = value`

## 客户端架构

### EntityBase（ClinetCSharp.Scripts）

Godot Node2D，包含：
- GridSize / GridPos — 格子坐标
- 外观属性（VisualSizeScale/BorderColor/BgColor 等）
- 血条/MP条/施法条/动作栏属性
- 标签属性（LabelTexts/LabelFontSizes 等）
- 渲染组件列表 `_renderComponents`
- 移动基础（Tween/IsMoving）

### 渲染组件（Scripts/RenderComponents/）

| 组件 | DrawOrder | 用途 |
|---|---|---|
| AppearanceComponent | 0 | DrawBody（方块+边框+背景） |
| HealthBarComponent | 100 | 血条 |
| MpBarComponent | 100 | MP条 |
| CastBarComponent | 200 | 施法条 |
| ActionBarComponent | 200 | 动作栏（技能名+进度） |
| LabelComponent | 300 | DrawString 标签（Monster/Npc） |
| RichLabelComponent | 300 | RichTextLabel 标签（Player，空操作） |
| LevelBadgeComponent | 400 | 等级徽章（Player） |

### 子类渲染组件组合

| 实体 | 组件列表 |
|---|---|
| Monster | Appearance, HealthBar, MpBar, CastBar, ActionBar, Label |
| Npc | Appearance, HealthBar, MpBar, Label |
| Player | Appearance, HealthBar, MpBar, CastBar, ActionBar, RichLabel, LevelBadge |

### Facade 模式

所有属性和 setter 保留在 EntityBase 上，渲染组件只管"绘制逻辑"。
外部代码（DebugPanel/EntityProfileManager 等）不需要任何改动。

## 协议架构

### 新增协议（game.proto）

**EntityType 枚举（9种）：**
Player=0, Monster=1, Npc=2, Boss=3, Pet=4, Guard=5, GatherNode=6, Portal=7, Chest=8

**ComponentType 枚举（6种）：**
Combat=0, Move=1, Cast=2, AI=3, Interact=4, Gather=5

**组件数据消息：**
- CombatComponentData — hp/max_hp/mp/max_mp/level/attrs/in_combat
- MoveComponentData — speed_ms/is_moving/target_x/target_y
- CastComponentData — equipped_skills/casting_skill_id
- InteractComponentData — npc_id/npc_type/in_combat

**统一实体消息：**
- EntitySnapshot — entity_id/type/components/x/y/name/template_id + 组件数据
- MapEntityListNotify — 进入地图时下发全部实体
- EntityCreateNotify — 实体创建通知
- EntityDestroyNotify — 实体销毁通知

**消息 ID：** 410-412

### 旧协议

旧协议消息（MonsterMoveNotify/MonsterStateBatchNotify 等）暂时保留，等新协议完全替代后再删除。

---

## 扩展性

新增实体类型只需：
1. **服务端**：在 EntityComponentConfig 添加组件组合
2. **客户端**：添加渲染组件组合（或复用现有渲染方式）
3. **协议**：EntityType 枚举添加值
