# 野怪标签数据绑定

> 状态：已确认
> 日期：2026-05-10

## 1. 背景

当前怪物头顶标签仍保留了旧的静态文本思路：

- 运行时会写入名字、等级或临时属性文案
- `EntityProfile` / DebugPanel 仍可能保存旧的标签预览内容
- 一旦 profile 中存在非空 `ContentPreview`，运行时真实值会被覆盖

这会让“怪物标签显示的是什么”变得不稳定，也不利于后续在调试面板中只调样式、不改数据来源。

## 2. 目标

将野怪前三行标签改成明确的数据绑定：

1. `名字`：绑定 `Monster.Level + Monster.MonsterName`，显示格式为 `LV.99 野狼`
2. `品质`：绑定怪物配置中的 `MonsterDef.Quality`，未配置时回退为 `普通`
3. `状态`：绑定 `Monster.CurrentState`，显示为中文状态文案

第四行暂不承载怪物核心信息，默认隐藏，保留给后续扩展。

## 3. 约束

### 3.1 Profile 继续只管样式，不管怪物真实数据

Monster profile 中：

- 仍可控制标签显隐、字号、偏移、粗体等样式
- 不再用 `ContentPreview[0..2]` 覆盖怪物的名字/品质/状态

也就是说，怪物前三行标签的“内容来源”归运行时怪物实例负责，Profile 只负责“怎么显示”。

### 3.2 旧配置迁移

已有用户配置里，怪物 profile 可能保存了旧的文本预览内容，例如：

- 名字行里写了固定怪名
- 第二、三行里写了等级/属性

为了避免这些旧值继续覆盖真实数据，加载配置后要对所有 `entity_type=monster` 的 profile 做一次标准化：

- `Names[0..2]` 重置为 `名字 / 品质 / 状态`
- `ContentPreview[0..2]` 清空
- `LockedProperties` 锁定 `content_0..2`
- `Visible[0..2]` 设为 `true`
- `Visible[3]` 默认设为 `false`

## 4. 数据来源

### 4.1 名字

- 来源：服务端 `MonsterInfo.name`
- 等级来源：服务端 `MonsterInfo.level`
- 存储：`Monster.MonsterName`
- 显示格式：`LV.{level} {name}`

### 4.2 品质

- 来源：客户端怪物配置 `monster_config.json` 的 `quality`
- 类型：字符串，例：`普通 / 精英 / 首领`
- 回退：未配置时显示 `普通`

本次不扩 proto，不把“品质”当成网络权威字段；它属于怪物静态定义的一部分，先从本地怪物配置读取。

### 4.3 状态

- 来源：运行时 `Monster.CurrentState`
- 数据通路分两段：
  - 移动态：继续来自 `MonsterMoveNotify.state`
  - 原地战斗态：由 `CombatStateNotify` 在客户端补充同步

显示时将状态码转成中文文案，例如：

- `idle` -> `待机`
- `patrol` -> `巡逻`
- `chase` -> `追击`
- `return` -> `回撤`
- `combat` -> `接战`
- `combat_hold` -> `对峙`
- `combat_chase` -> `追杀`
- `combat_ranged_hold` -> `远程瞄准`
- `combat_ranged_chase` -> `远程追击`
- `combat_cast_hold` -> `蓄法`
- `combat_cast_chase` -> `施法追击`
- `dead` -> `死亡`

未知状态直接回显原始字符串，避免调试时信息丢失。

## 5. 落地方案

### 5.1 Monster 实例负责刷新绑定标签

Monster 新增统一刷新入口，负责同步：

- `LabelTexts[0] = 名字`
  - 具体格式为 `LV.{Level} {MonsterName}`
- `LabelTexts[1] = 品质`
- `LabelTexts[2] = 状态`

当以下字段变化时自动刷新：

- `Setup(...)`
- `CurrentState` 更新
- 质量字段初始化

### 5.1.1 静止状态同步

此前客户端只在怪物移动通知里改 `CurrentState`，导致：

- 怪物原地接战时，标签仍停留在上一次移动状态
- 远程怪进入射程停住后，仍可能显示 `巡逻`
- 施法怪站桩读条时，标签不会变成战斗/施法态

本次改成：

- 移动中的怪物仍以 `MonsterMoveNotify.state` 为准
- 参与 `CombatStateNotify` 的怪物，如果当前未移动，则补写为对应的战斗驻留状态
- 已离开 `CombatStateNotify` 且当前仍停留在 `combat_*` 的怪物，回退为 `idle`，等待下一次 overworld 状态刷新

### 5.2 MonsterProfile 默认值调整

默认 monster profile 的 labels 组件改成：

- 名称：`名字 / 品质 / 状态 / 预留`
- 前三行内容锁定
- 第四行默认隐藏

## 6. 预期收益

- 野怪标签真正和怪物数据关联，内容来源清晰
- DebugPanel 不再误改怪物真实标签内容
- 后续扩展怪物标签时，只需新增绑定字段，不必再和 profile 预览逻辑缠在一起
