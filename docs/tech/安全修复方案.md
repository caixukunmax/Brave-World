## S1：TokenSecret 硬编码且已提交 Git

### 现状

**步骤3：更新 .gitignore**

**步骤6：清理 Git 历史**（可选，如果仓库已公开）

## S2：密码存储用 MD5+salt

### 现状
- `PasswordHasher.cs`：`base64(salt):MD5(salt+password)`
- MD5 是快速哈希，GPU 每秒可尝试数十亿次
- 即使有 salt，暴力破解成本极低

### 修复方案

**方案A：bcrypt（推荐）**
```csharp
// 安装 NuGet 包
// <PackageReference Include="BCrypt.Net-Next" Version="4.0.3" />

public static string HashPassword(string password)
{
    return BCrypt.Net.BCrypt.HashPassword(password, workFactor: 12);
}

public static bool VerifyPassword(string password, string hashedPassword)
{
    return BCrypt.Net.BCrypt.Verify(password, hashedPassword);
}
```

**方案B：PBKDF2（无需额外依赖）**
```csharp
public static string HashPassword(string password)
{
    var salt = RandomNumberGenerator.GetBytes(16);
    var hash = Rfc2898DeriveBytes.Pbkdf2(
        password, salt, iterations: 600_000, HashAlgorithmName.SHA256, 32);
    return $"{Convert.ToBase64String(salt)}:{Convert.ToBase64String(hash)}";
}
```

### 迁移策略
- 新用户：直接用新算法
- 旧用户：登录时验证旧 MD5 hash → 通过后用新算法重新哈希 → 更新数据库
- 保留旧格式识别：`oldHash.Contains(":") && oldHash.Split(':')[1].Length == 24`（MD5 base64 长度）

### 验证
- [ ] 新注册用户密码用 bcrypt/PBKDF2 存储
- [ ] 旧用户登录时自动迁移到新算法
- [ ] 迁移后数据库中不再有 MD5 格式的密码哈希

## S3：Token 签名用 MD5

### 现状
- `TokenGenerator.cs`：`MD5(secret + payload)`
- MD5 碰撞攻击可伪造有效 Token
- HMAC-MD5 更安全但仍不建议

### 修复方案

```csharp
public static string GenerateToken(string secret, string payload)
{
    var key = Encoding.UTF8.GetBytes(secret);
    using var hmac = new HMACSHA256(key);
    var hash = hmac.ComputeHash(Encoding.UTF8.GetBytes(payload));
    return Convert.ToBase64String(hash);
}

public static bool ValidateToken(string secret, string payload, string token)
{
    var expected = GenerateToken(secret, payload);
    return CryptographicOperations.FixedTimeEquals(
        Encoding.UTF8.GetBytes(expected),
        Encoding.UTF8.GetBytes(token));
}
```

### 注意
- `CryptographicOperations.FixedTimeEquals` 防止时序攻击
- 修改签名算法后，所有已发放的 Token 失效，用户需重新登录
- 建议与 S1 同步修复，一次性更换密钥+算法

### 验证
- [ ] Token 签名使用 HMAC-SHA256
- [ ] Token 验证使用固定时间比较
- [ ] 旧 Token 全部失效，用户需重新登录

## S4：GatewayToken TTL 7天

### 现状
- GatewayToken 有效期 7 天
- 被盗后攻击者 7 天内可自由使用

### 修复方案

**短期**：缩短 TTL 到 2 小时
```csharp
// GameConstants.cs
public const int GatewayTokenTtlSeconds = 7200; // 2小时
```

**长期**：添加刷新机制
```
1. 登录获取 AccessToken（TTL=2h）+ RefreshToken（TTL=7d）
2. AccessToken 过期后用 RefreshToken 换新 AccessToken
3. RefreshToken 只能使用一次（轮换）
4. 服务器维护 RefreshToken 黑名单（用户登出/修改密码时加入）
```

### 验证
- [ ] GatewayToken TTL ≤ 2 小时
- [ ] Token 过期后客户端自动重新登录（非静默刷新）

```csharp
// appsettings.json
"Game": {

if (account == null)
{
    if (!_config.AllowAutoRegister)

    // ... 自动注册逻辑
}
```

### 现状
- 连接字符串：`mongodb://127.0.0.1:27017/tslua2`
- 无用户名/密码

### 修复方案

**开发环境**：可保持无认证（本地访问）

**生产环境**：
```bash

    roles: [{role: "readWrite", db: "tslua2"}]
  });

# 2. 启用认证（mongod.conf）
security:
  authorization: enabled

# 3. 更新连接字符串
mongodb://tslua2_admin:密码@127.0.0.1:27017/tslua2
```

## S9/S10：NuGet 依赖安全漏洞

### 现状
- Snappier 1.0.0 CVE-2026-44302（High）：畸形帧解压无限循环 DoS
- SharpCompress 0.30.1 CVE-2026-44788（Moderate）：目录遍历 zip slip
- 均为 MongoDB.Driver 3.2.1 的传递依赖

### 修复方案

```bash
# 升级 MongoDB.Driver
dotnet add package MongoDB.Driver --version 3.8.1
```

MongoDB.Driver 3.8.1 依赖更新版本的 Snappier 和 SharpCompress，修复已知漏洞。

### 验证
- [ ] `dotnet list package --vulnerable` 无高危漏洞
