## Workflow Rules
- 当用户每次加新需求时，必须先和已有的需求文档进行比对
- 检查新需求是否能与现有需求完美融合、是否存在矛盾
- 若发现矛盾，拒绝执行该需求，并向用户提出修改建议
- 当前处于开发阶段，无论是写新需求还是修 bug，都必须追求完美和永久的解决方案，拒绝临时方案或权宜之计
- 开始实现需求时，如果需求文档需要变动，必须先整理并更新 docs 目录下的文档，确认无误后再开始写代码
