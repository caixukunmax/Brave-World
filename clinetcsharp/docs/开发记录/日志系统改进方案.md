# 日志系统改进方案

## 问题描述

当前 `scripts/log_collector.gd` 的日志拦截功能未实际实现：

```gdscript
func _setup_log_interception():
    # 日志收集器不需要复杂的拦截设置
    # 未来可以通过重定向 print 来实现，目前通过其他脚本调用 add_log
    pass
```

这导致 `scripts/screenshot_tool.gd` 在截图时只能获取到**主动调用** `LogCollector.add_log()` 的日志，无法捕获：
- 项目内大量现有的 `print()` 输出
- `push_error()` / `push_warning()` 输出
- Godot 引擎运行时报错和警告

## 目标

让截图工具在按下 F12 时，能够获取到**完整的 Godot 输出日志**，包括所有 `print()`、`push_error()`、引擎报错，无需修改现有代码中的任何 `print()` 调用。

## 方案设计

### 核心思路

启用 Godot 的**文件日志（File Logging）**功能，让引擎自动把所有输出写入磁盘日志文件。`LogCollector` 改为**实时读取该日志文件**，将内容同步到自己的日志缓存中。

### 具体改动

#### 1. 启用 Godot 文件日志

在 `project.godot` 中添加以下配置：

```ini
[debug]

file_logging/enable_file_logging=true
file_logging/log_path="user://logs/godot.log"
```

这样 Godot 会自动把 `stdout` / `stderr`（包括所有 `print()` 和引擎报错）写入 `user://logs/godot.log`。

#### 2. 重写 `log_collector.gd`

- 删除空的 `_setup_log_interception()`
- 新增 `_setup_file_log_reader()`：
  - 打开 `user://logs/godot.log`
  - 维护读取偏移量，只读取新增内容
- 在 `_process(delta)` 中定期调用 `_read_new_logs()`，将新日志按行解析为 `LogEntry`
- 保留 `add_log()` 方法，供其他脚本主动添加带级别的结构化日志
- 日志解析规则：
  - 包含 `"ERROR"` 或 `"SCRIPT ERROR"` 的行 → `ERROR` 级别
  - 包含 `"WARNING"` 的行 → `WARNING` 级别
  - 其他行 → `INFO` 级别

#### 3. 截图工具无需改动

`screenshot_tool.gd` 已经通过 `log_collector.get_recent_logs()` 和 `log_collector.get_error_logs()` 获取日志。`LogCollector` 内部缓存充实后，截图自然包含完整输出。

## 兼容性

- **零侵入**：不需要修改任何现有脚本中的 `print()` 调用
- **运行时启用**：如果文件日志因权限问题无法启用，`LogCollector` 会回退到当前行为（只收集主动添加的日志），并在控制台打印提示
- **跨平台**：`user://logs/godot.log` 在所有 Godot 支持的平台都有效

## 扩展性（未来可选）

如果后续需要更精细的日志分类（如 `Logger.info()` / `Logger.error()`），可以：
1. 新建 `scripts/logger.gd` Autoload
2. 提供带级别的日志方法
3. 内部同时调用 `print()` 和 `LogCollector.add_log()`

但本次改进以**最小改动、最大收益**为原则，先解决"获取不到 Godot 输出"的核心问题。

## 验收标准

- [x] `project.godot` 中已启用 `file_logging/enable_file_logging`
- [x] 运行游戏后，`user://logs/godot.log` 文件存在且包含 `print()` 输出
- [x] 按 F12 截图后，保存的 `logs.txt` 中包含游戏启动以来的所有 `print()` 和错误日志
- [x] 现有 `print()` 调用无需任何修改
- [x] `LogCollector` 在文件日志不可用时能优雅降级
